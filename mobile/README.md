# Вандроўка — Expo Go

Обязательный способ разработки — Expo Go на физическом Android-телефоне.
Эмулятор не запускаем. Сейчас доступны стартовый экран, подсказки, три вкладки, список мест Минска
и карточка из backend, карта Mapbox через WebView, фото/GPS-подтверждение, XP, уровни и история.

## Запуск

Нужны Node.js 22.23.2, npm и Expo Go, совместимый с SDK 58.
Проект обновлён с SDK 57 до 58. Версия Expo Go и major SDK проекта должны совпадать;
совместимые Android-версии доступны на официальной странице https://expo.dev/go.
Java/Android SDK и собственный APK для этого способа запуска не нужны.

```bash
cd mobile
nvm use
npm ci
npm start
```

Телефон и компьютер должны быть в одной локальной сети. Откройте проект
по QR-коду в Expo Go. Скрипт явно задаёт `--go`, даже при установленном
expo-dev-client (он сохранён для необязательных собственных сборок).

## По USB

Нужны adb, отладка по USB и разрешение подключения на телефоне.
`adb devices` должен показывать физический телефон в состоянии `device`.
Замените PHONE_SERIAL его серийным номером:

```bash
adb -s PHONE_SERIAL reverse tcp:8081 tcp:8081
npm run start:usb
```

В Expo Go введите `exp://127.0.0.1:8081`. Можно открыть ссылку через adb:

```bash
adb -s PHONE_SERIAL shell am start -a android.intent.action.VIEW -d exp://127.0.0.1:8081
```

Эти команды не запускают эмулятор и не устанавливают собственный APK.

## Конфигурация и ограничения

Адрес backend хранится в `mobile/.env.local` (не в корневом env).
Для USB задайте в локальном файле адрес:

```dotenv
EXPO_PUBLIC_API_URL=http://127.0.0.1:8080
```

Запустите backend отдельно (см. корневой README), затем:

```bash
adb -s PHONE_SERIAL reverse tcp:8080 tcp:8080
adb -s PHONE_SERIAL reverse tcp:8081 tcp:8081
npm run start:usb
```

8080 — HTTP API, 8081 — Metro. Reverse необходимо повторять после переподключения
телефона/перезапуска adb. Для независимой проверки откройте в браузере телефона
`http://127.0.0.1:8080/health`: ожидается HTTP 200 и `{"status":"ok"}`.
Это проверяет телефон → backend. В API-клиенте также доступен метод `api.health()`.

Для Wi-Fi замените значение на адрес компьютера, например
`EXPO_PUBLIC_API_URL=http://192.168.1.100:8080`. Телефон должен быть в той же сети;
проверьте доступ к порту 8080 и отсутствие изоляции клиентов в Wi-Fi.
В браузере телефона откройте `http://192.168.1.100:8080/health`.
Адреса `0.0.0.0`, `postgres`, `api` не являются адресом компьютера для телефона.

После изменения env полностью перезагрузите проект в Expo Go (Reload).
`src/config/api.ts` читает переменную через поддерживаемое Expo обращение
`process.env.EXPO_PUBLIC_API_URL`. При отсутствии переменной используется USB-адрес;
пустое или некорректное значение вызывает ApiConfigurationError.
Поддерживается только корневой HTTP(S)-адрес без пути, credentials, query и fragment;
завершающий `/` удаляется. API-клиент использует
`getApiBaseUrl()`. Раздел «Исследовать» загружает места и категории Минска;
карточка запрашивается по числовому ID.
Серверные токены Mapbox и пароли нельзя помещать в EXPO_PUBLIC-переменные.

Карта по решению пользователя — Mapbox GL JS через react-native-webview.
WebView входит в Expo Go SDK 58. Пользователь подтвердил работу карты на телефоне
в Expo Go. Приёмка самостоятельного APK описана в отчёте дня 13.
Серверные Mapbox Matrix/Directions сохраняются.
Нативный Mapbox SDK не используем.
Новые библиотеки должны поддерживать Expo Go используемой версии SDK.

`android/` и `ios/` генерируются Expo и игнорируются Git. Ранее собранный
ARM64 development APK относится к другому способу запуска; для Expo Go он не нужен.
Профили EAS сохранены для будущей автономной preview/release-сборки.

## Облачная сборка APK

Профиль `preview` использует окружение EAS `preview` и выдаёт APK для телефона.
В папке `mobile` выполнить вход и привязку к своему проекту Expo.

```bash
npx eas-cli@latest login
npx eas-cli@latest init
```

В Expo Dashboard открыть Project settings → Environment variables и добавить
для окружения `preview` две переменные с видимостью Plain text.

- `EXPO_PUBLIC_API_URL` с HTTPS-адресом развёрнутого backend.
- `EXPO_PUBLIC_MAPBOX_ACCESS_TOKEN` с публичным `pk.…` из локальной конфигурации.

Локальный `.env.local` исключён из Git и загрузки исходников в EAS.
Эти публичные значения включаются в клиентский bundle. Серверные секреты
хранятся в окружении backend. Указанный в EAS API должен содержать каталог
и миграции до версии 16.

```bash
npx eas-cli@latest build --platform android --profile preview
```

При первой сборке выбрать создание Android keystore, если собственного ключа
для `by.vandrouka.app` ещё нет. Для последующих сборок использовать тот же ключ.
Скачать готовый APK по ссылке EAS и выполнить приёмку из
[этапа 13 ноября](../docs/day-13-november-acceptance.md).
При `appVersionSource=local` перед следующей сборкой для проверки обновления
увеличить `expo.android.versionCode` в `app.json` относительно предыдущего APK.

Настройка переменных описана в
[документации EAS](https://docs.expo.dev/eas/environment-variables/manage/).

## Навигация

В исследовании загружается серверный список мест Минска. Выбор места
открывает его карточку поверх вкладок.
Профиль показывает серверные XP, уровень, достижения и коллекцию. «Посещения»
показывает личную историю и фотографии. У нового аккаунта отображаются
начальный прогресс и пустая история.
Маршруты находятся в `src/app/`, компоненты экранов — в `src/components/`.
Подробности и сценарии ручной проверки: [отчёт 17 октября](../docs/day-17-mobile-navigation.md).

## Общие компоненты

`src/components/ui/`: AppButton (disabled/loading), LoadingState, ErrorState
(повтор и необязательный Request ID), EmptyState, PlaceCard и общие цвета.
Список и карточка используют загрузку, ошибку с повтором и пустые состояния.

## API-клиент

`src/api/client.ts`: health, города, категории города, список мест с category/q,
карточка по числовому ID. Проверяются необходимые мобильному клиенту поля JSON;
остальные поля ответа пока не используются. HTTP APIError сохраняет status,
code и X-Request-ID. Сетевые ошибки не раскрывают текст внутренних исключений.
Таймаут 10 секунд включает чтение тела ответа. Автоматических повторов нет.
Ошибочная конфигурация адреса показывается как ошибка загрузки.

`useApiResource` отменяет запрос при уходе с экрана, смене ID и размонтировании,
не применяет запоздалые результаты. При возврате на экран данные загружаются
заново. Отмена не показывается как ошибка. «Повторить» выполняет новый запрос.
Backend должен работать отдельно; при выключенном сервере ожидаема ошибка связи.
Приватные профиль, история и прогресс используют авторизованные запросы
и очищаются при смене владельца. Карта получает места из публичного каталога.

`npm test` проверяет контракт и отказы на фиктивном fetch без сети/Mapbox/БД.
19 октября пользователь подтвердил сквозную проверку в Expo Go на CMF Phone 2
по Wi-Fi: список, карточка, навигация и восстановление после остановки API.

## Карта Mapbox (этап 18 октября)

В «Исследовать» теперь есть режимы «Карта / Список». Карта использует Mapbox GL JS
3.33.0, пользовательский стиль Mapbox Standard, центр Минска и маркеры из того же backend-каталога.
Нажатие на маркер открывает обычную карточку по числовому ID. Список остаётся
доступным при ошибке WebGL, сети, отсутствующем или неверном токене.

Добавьте в `mobile/.env.local` отдельный **публичный** токен Mapbox:

```dotenv
EXPO_PUBLIC_MAPBOX_ACCESS_TOKEN=pk.ВАШ_ПУБЛИЧНЫЙ_ТОКЕН
```

Это значение включается в приложение. **Секретный `sk.*` из backend не копировать.**
Используйте публичный токен с разрешениями для чтения стилей/шрифтов карты;
ограничения URL должны допускать выбранный WebView-origin. У inline HTML может
быть origin null/about:blank — web-токен с привязкой к домену сайта может дать 403.
Не ослабляйте существующий серверный токен: для мобильной карты нужен отдельный.
После изменения env сделайте полный Reload в Expo Go.

При открытии карты идут реальные запросы Mapbox (JS/CSS, стиль, тайлы, шрифты),
которые могут расходовать квоту. Без валидного pk-токена WebView не создаётся.
Нет автоматического цикла перезагрузки: повтор только по кнопке пользователя.
При переключении карта/список и возврате из карточки WebView сохраняется,
обновляются только маркеры; полный Reload приложения и ручной повтор создают карту заново.
Кэш тайлов не является обещанием работы офлайн. GPS и построение маршрутов
на этом этапе не подключены. Логотип/атрибуция Mapbox сохранены.

Проверка на телефоне: Минск и маркеры → выбор места → назад → список/карта;
проверить жесты, масштабирование и атрибуцию. Затем отдельно проверить отсутствие
токена, неверный токен, недоступность интернета и backend. На пустом каталоге
показывается пустое состояние. Ни один сценарий не требует эмулятора.

Текущий стиль: `mapbox://styles/mpaprotski911/cmvfoqaqv00fl01s60qij53my`.
URL хранится в `MAP_STYLE_URL` (`src/map/document.ts`). Опубликованный стиль
проверен публичным токеном: HTTP 200. Изменения в Studio нужно публиковать;
для проверки обновлённого оформления выполните Reload в Expo Go.

Inline WebView использует виртуальный baseUrl `https://app.vandrouka.local/`
для стабильного HTTPS-origin. Сеть к этому адресу не запрашивается. Если у
публичного Mapbox-токена настроены allowed URLs, учитывайте данный origin.

## Карточка и геолокация (19 октября)

Карточка показывает время осмотра, билеты, расписание с перерывами/исключениями,
местный часовой пояс и ссылки-источники. Для демонстрационной подборки API
также отдаёт обложку и атрибуцию из внешнего DATA_DIR. «Как добраться» открывает
внешние карты, ошибки обрабатываются.

«Моё местоположение» определяет одну свежую позицию только по нажатию.
Синий маркер — положение на момент запроса, не фоновое слежение. Подписка GPS
удаляется после результата/таймаута/отмены; при уходе или фоне точка очищается.
Повторное получение — вручную. Для постоянного запрета доступен переход к настройкам.
В Expo Go системный диалог относится к разрешениям самого Expo Go.
Сценарии проверки: [отчёт этапа](../docs/day-19-place-location.md).

## Вход и восстановление сессии — этап 22 октября

В «Профиле» доступны вход/регистрация/выход. Access действует 24 часа,
refresh-family — 30 дней с одноразовой ротацией. Expo хранит сессию в SecureStore,
проверяет её после перезапуска и сохраняет отзыв при выходе без сети.
После обновления выполните миграции и пересоберите API; затем перезагрузите Expo Go.
Проверки и оставшиеся сценарии на телефоне: [отчёт дня 22](../docs/day-22-mobile-auth.md).

## Камера и загрузка — день 26

Ниже состояние этапа 26; текущий полный сценарий дополнен днём 27.

В карточке места откройте **Сделать фото места**. Авторизованному пользователю
доступны задняя камера, предпросмотр, пересъёмка и приватный upload.
Перед upload получаем новый foreground fix: известная accuracy ≤30 м,
фиксация не старше 30 секунд. Это предварительная проверка; окончательное решение
о посещении принимает сервер. Отправка confirm и отображение XP добавлены
этапом 27, описанным ниже.

`expo-camera ~57.0.6` и `expo-file-system ~57.0.7` установлены через `expo install`.
Оба доступны в Expo Go; эмулятор и development build для этого этапа не нужны.
В app.json отключено добавление Android microphone permission; галерея,
background location и base64 не используются. После обновления зависимостей
перезапустите Metro: `npm start -- --clear`.

Draft существует только на экране для текущего аккаунта/места. Уход в фон/blur
прерывает GPS/upload и выключает preview камеры, снимок остаётся для повтора.
Пересъёмка и закрытие экрана удаляют локальный cache-файл и пытаются удалить
известное загруженное фото. Неизвестный исход upload/отсутствие сети покрывает
серверная очистка: uploading lease 15 минут, готовый неподтверждённый файл 24 часа.
Черновик не восстанавливается после перезапуска приложения.

[Отчёт и обязательная физическая проверка](../docs/day-26-mobile-camera.md).

## Подтверждение посещения — день 27

После upload нажмите **Подтвердить посещение**: новый foreground GPS → серверный
confirm → +100/0 XP или объяснение отказа. Кнопка блокируется на время запроса.
После сохранённого отказа повтор получает новый GPS и UUID. После таймаута
**Проверить результат** отправляет прежнее тело с прежним ключом.

До отправки попытка записывается в SecureStore, отдельно по origin/user/place.
Она содержит UUID, photo metadata и точное тело с GPS; GPS хранится зашифрованно
только для восстановления неопределённого исхода. Пароли/токены в эту запись не входят.
После окончательного ответа запись удаляется. На web нет незашифрованного fallback.

При повторном открытии карточки/камеры того же места незавершённый запрос
восстанавливается; камера пока не запускается. Фото с таким запросом или с
confirmed visit не удаляется обычной очисткой черновика. Суммарный баланс
и уровни добавлены днём 29, история подключена этапом 30.

Добавлен `expo-crypto ~57.0.4` (UUID/SHA-256), совместимый с Expo Go.
После установки зависимости перезапустите Metro. Подробности:
[день 27](../docs/day-27-mobile-confirmation.md).

## Проверка дня 28

Операции экрана съёмки закреплены за его user ID (`withAccess(..., owner)`):
старый экран не отправляет запрос под новым аккаунтом. Автоматическая очистка
вызывает `discardPhoto` с серверным `unconfirmed_only=true`, чтобы не удалить фото,
которое уже успели подтвердить; явное удаление владельцем остаётся отдельным действием.

Локальная интеграция из корня репозитория:
`node --experimental-strip-types scripts/verify_game_loop.mjs`.
[Отчёт, ограничения и физическая проверка](../docs/day-28-integration.md).

## Прогресс — день 29

Профиль показывает общий XP, уровень, остаток до следующего уровня и полосу
по серверным границам `GET /v1/me/progress`. На уровне 10 XP растёт дальше,
следующий порог отсутствует. Данные обновляются при фокусе профиля, возврате
из фона и вручную; после confirmed есть **Посмотреть прогресс**.

Запрос привязан к текущему owner ID и отменяется при уходе/смене аккаунта.
Ошибка загрузки не подменяется 0 XP. Новых native-модулей нет; физическая проверка
профиля и цикла дня 28 ещё не записана. [Отчёт](../docs/day-29-progress.md).

Вкладка «Посещения» загружает историю подтверждённых визитов с сервера,
показывает дату, XP и личное фото по кнопке. Есть пагинация и повтор загрузки;
при уходе с экрана/в фон приватные данные очищаются из памяти.
Для проверки на телефоне: подтвердить посещение, открыть фото в истории,
перезапустить Expo Go и проверить историю снова; сменить аккаунт и убедиться,
что чужая история и фото не показываются.

Личная карта (день 31): после входа «Исследовать» показывает посещённые/новые
места и фильтры «Все / Мои места / Новые» для карты и списка. История читается
полностью; ошибка не превращает неизвестный статус в «не посещено».
После подтверждения вернитесь на вкладку, чтобы обновить отметки.

Надёжность синхронизации: приватные XP, фото и отметки карты очищаются
при уходе с экрана/в фон и перечитываются при возвращении. Ошибка не показывает
старый XP или ложный успех. Upload повторяется вручную; неопределённый confirm
повторяет сохранённый запрос с прежним ключом. [Проверка offline](../docs/day-01-november-sync.md).

Текущее окружение обновлено до Expo SDK 58 для совместимости с установленным
Expo Go. [Изменения и проверки миграции](../docs/expo-sdk-58.md).
Исторические версии пакетов в отчётах этапов выше относятся к SDK 57.

После подтверждённого удаления аккаунта очищается индексированный pending-confirm
