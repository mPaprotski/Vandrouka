# Вандроўка

[![CI](https://github.com/mPaprotski/Vandrouka/actions/workflows/ci.yml/badge.svg)](https://github.com/mPaprotski/Vandrouka/actions/workflows/ci.yml)

Платформа исследования города через прогулки, культурный контент и игру.
Пользователь открывает исторические места, подтверждает посещения фото и GPS,
получает XP и сохраняет личную историю путешествий.

**[Единый план разработки MVP](docs/development-plan.md)** — 16 октября — 15 ноября 2026.
Первый клиент: Expo + React Native + TypeScript для Android. XP и уровни обязательны;
достижения/коллекции — при наличии времени, партнёрские награды — после MVP.
Готовый backend описан ниже; игровые модули и мобильное приложение ещё предстоит реализовать.

**Принято решение перейти на Mapbox API** для маршрутизации, матрицы,
подложки карты и геокодирования. [План миграции](docs/mapbox-migration.md)
заменяет исходное решение о локальной Valhalla. CLI уже использует Mapbox
Matrix/Directions; для реального запуска нужен `MAPBOX_ACCESS_TOKEN`.
Карта и геокодирование будут подключены на мобильном этапе.

Реализованы каркас Go API, PostgreSQL, миграции, импорт YAML, каталог мест,
клиент Mapbox Matrix/Directions, жадный планировщик, оптимизация 2-opt/swap
и до трёх вариантов маршрута по четырём профилям (CLI).
Добавлены настраиваемая оценка, метки с порогом 10%, объяснения маршрутов
и сравнение вариантов по времени, расстоянию, билетам и составу мест.
Доступен POST `/v1/routes/generate` с проверкой Matrix/Directions.
Доступен POST `/v1/routes/recalculate` для операций add/remove.
Мобильное приложение находится в разработке.

## Запуск

Нужны Docker Compose и Go 1.25+.
Все команды Makefile запускаются из корня репозитория.

```bash
cp -n backend/.env.example backend/.env
# Замените MEDIA_S3_SECRET_KEY в backend/.env случайным секретом.
docker compose --env-file backend/.env up -d postgres minio
make migrate-up
make import
docker compose --env-file backend/.env up -d --build api
curl http://localhost:8080/health
curl http://localhost:8080/v1/cities/minsk/places
```

API — `localhost:8080`, PostgreSQL — `localhost:25432`, приватный MinIO — `127.0.0.1:29000` (консоль `29001`).
`/health` проверяет также доступность PostgreSQL.
Для каталога Mapbox-токен не нужен. Для планировщика задайте
`MAPBOX_ACCESS_TOKEN` в окружении. Valhalla удалена из активного Compose после успешной проверки Mapbox.
Исторические инструкции и данные сохранены.

## Локальный backend

Конфигурация читается из переменных окружения; файл `.env` автоматически
не загружается. Можно использовать предоставленный пример:

```bash
docker compose --env-file backend/.env up -d postgres minio
make migrate-up
cd backend
set -a
. ./.env
set +a
go run ./cmd/api
```

При запущенном API-контейнере для локального API выберите другой `HTTP_PORT`.
Настройки разработки из `.env.example` не предназначены для публичного сервера.

## Команды

```bash
make up             # сборка и запуск PostgreSQL + MinIO + API
make down           # остановка с сохранением тома БД
make test           # Go-тесты; интеграционные требуют TEST_DATABASE_DSN
make lint           # go vet и проверка форматирования
make migrate-up     # применение миграций
make migrate-status # статус миграций
make migrate-down   # откат одной миграции
make migrate-reset  # полный откат миграций, удаляет таблицы приложения
make import         # импорт мест и проверка доступности источников
```

DSN для Makefile можно переопределить: `make migrate-status DSN='postgres://...'`.
Для CLI установите `POSTGRES_DSN` в окружении.

## Данные и импорт

Один YAML на место в `data/places/minsk/`. Формат, обязательные сведения,
проверки и правила актуализации описаны в [data/README.md](../data/README.md).
Набор содержит 60 мест. Первые 15 проверены в [отчёте дня 4](docs/day-4.md),
ещё 20 добавлены при расширении каталога. Из пользовательского GPX Globus
добавлены 25 мест и сопоставлены 8 существующих; происхождение записей и
ограничения описаны в [отчёте импорта GPX](docs/globus-import.md).
Новые сведения из выгрузки 2015 года требуют актуальной проверки.

```bash
make import
# Без проверки сети, из backend с установленным POSTGRES_DSN:
go run ./cmd/import -check-links=false ../../data/places/minsk
```

Импорт атомарен. Повторный запуск обновляет записи по `(city_id, slug)` и
сохраняет ID; связанная информация заменяется без накопления дублей.
Недоступные источники дают предупреждение, успешный импорт завершается кодом 0.

## Планировщик и CLI

Минимальный жадный алгоритм (пакет `internal/planner`) строит пешеходный маршрут
с соблюдением бюджета времени, темпа ходьбы, расписаний работы мест (`CanVisit`)
и бюджета на входные билеты:

```bash
cd backend
POSTGRES_DSN='postgres://postgres:postgres@localhost:25432/vandrouka?sslmode=disable' \
go run ./cmd/planner --budget 180 --categories museums,architecture
```

Подробное описание алгоритма, правил и параметров: [docs/planner.md](docs/planner.md).

CLI по умолчанию формирует до трёх разных вариантов, оптимизирует их через
2-opt/swap и уточняет итоговый путь через Mapbox Directions. Для одного
маршрута: `--variants=false --profile=budget`; другие профили: `best_match`,
`more_places`, `less_walking`. `--optimize=false` отключает оптимизацию.
`--geometry=false` отключает Directions и оставляет оценки Matrix.
Перед запуском экспортируйте `MAPBOX_ACCESS_TOKEN`; токен не сохраняйте в Git.
Коэффициенты оценки задаются через `PLANNER_WALK_PENALTY` (за км),
`PLANNER_COST_PENALTY` (за BYN) и `PLANNER_UNVERIFIED_PENALTY` (за место).
Метки сравнивают итоговые маршруты после Directions; при одном варианте
или преимуществе менее 10% метка не выдаётся.
Каждый вариант сопровождается краткой сводкой; последующие варианты
сравниваются с первым. Неизвестные цены и часы явно отмечаются.

Ограничения этапа 19 октября проверены тестами: время, расписания,
сумма билетов, уникальность мест и направленные переходы. При неизвестной
цене итог отражает только подтверждённую стоимость; фактические расходы
могут быть выше лимита. Результаты сверки приведены в документации планировщика.

## Проверки

Для PostgreSQL-интеграции используйте отдельную тестовую БД:

```bash
docker compose --env-file backend/.env exec -T postgres createdb -U postgres vandrouka_test
make migrate-up DSN='postgres://postgres:postgres@localhost:25432/vandrouka_test?sslmode=disable'
cd backend
TEST_DATABASE_DSN='postgres://postgres:postgres@localhost:25432/vandrouka_test?sslmode=disable' \
  go test ./... -race -count=1
```

Интеграционные тесты записывают и изменяют тестовые данные.
GitHub Actions запускает [CI](https://github.com/mPaprotski/Vandrouka/actions/workflows/ci.yml)
на каждый push и pull request; доступен также ручной запуск `workflow_dispatch`.
Версия Go берётся из `backend/go.mod`, зависимости и сборки кешируются.

CI проверяет зависимости, форматирование, `go vet`, сборку всех команд,
полный цикл миграций, тесты с PostgreSQL и детектором гонок, повторный импорт
с сохранением ID и проверкой числа активных мест. Отдельная проверка сверяет
выборку GPX, манифест происхождения данных и наличие карточек каталога.
Отдельный job проверяет ограничения и расписания планировщика без внешних
сервисов, собирает CLI и проверяет отклонение некорректного бюджета до подключения
к базе данных и Mapbox. HTTP-заглушки проверяют Mapbox без реальных токенов
и платных вызовов.
Внешние ссылки в CI не запрашиваются: CLI использует `-check-links=false`.
Отдельный job проверяет Compose и собирает Docker-образ API.
PostgreSQL создаётся отдельно для каждого запуска; секреты для этих проверок
не нужны. При новом push предыдущий запуск для той же ветки отменяется.
Проверки доступности ссылок тестируются локальным HTTP-сервером без внешней сети.

### Внешние данные

Папка `../data` относительно репозитория монтируется read-only в `/app/data`.
В Compose `DATA_DIR=/app/data` — путь внутри контейнера. Другой путь на хосте
задаётся через `DATA_HOST_DIR=/opt/vandrouka/data docker compose --env-file backend/.env up -d --build`.
Папка должна существовать; Compose не создаёт пустую папку автоматически.
Для `go run` из `backend/` задавайте `DATA_DIR=../../data` (значение по умолчанию
`./data` отсчитывается от текущей рабочей директории). `.env` Go автоматически
не читает. `make import` использует `../data`; можно передать `make import DATA_DIR=/путь/data`.
Загрузка при старте проверяет YAML/JSON и пишет число файлов в лог; данные API
по-прежнему берутся из PostgreSQL после отдельного импорта. Ошибка справочников
пишется как предупреждение и не останавливает API. GPX остаётся источником
для отдельного скрипта импорта, а не автоматической загрузки в БД при старте.

### Проверки после переноса данных

CI не требует рабочей папки `../data` или Mapbox-токена. Интеграционные тесты
используют `backend/testdata/golden_catalog.yaml`; `scripts/export_test_catalog.py`
выгружает этот фиксированный снимок для проверки повторного CLI-импорта.
Это тестовая фикстура, а не источник обновлений рабочего каталога.
Проверка актуальной GPX-выгрузки остаётся локальной: `python3 scripts/check_catalog_sources.py`
(можно задать `DATA_DIR`). CI проверяет реальные JSON-ответы Go HTTP-теста по OpenAPI.

Проверен сквозной запрос генерации с PostgreSQL и Mapbox: 120 минут, museums,
seed=42, старт 24 октября 2026 в 11:00 Europe/Minsk; получены три варианта.
Для повторения используйте пример curl выше и добавьте `"categories":["museums"]`.
Вызов использует квоту Mapbox.

### Пересчёт выбранного маршрута

`POST /v1/routes/recalculate` принимает `{request, base_place_ids, change}`.
`request` — исходные параметры генерации; `base_place_ids` — ID остановок
выбранного варианта в их порядке. `change` — `{"type":"remove","place_id":ID}`
или `{"type":"add","place_id":ID}`. Используйте ID из вашего каталога.
Ответ содержит один `variant` и `diff` (новый маршрут минус свежий исходный).
Удалённое место исключается из заполнения, добавляемое обязательно присутствует.
Лимит всей операции — 180 секунд; невозможное изменение или исходный маршрут
дают 422, неизвестные/неактивные места — 404, ошибка маршрутизации — 503.
Пустой маршрут после удаления возвращается с 200. Pin пока не поддерживается.

Пример удаления (нужен `jq`). Сохраните параметры генерации в `/tmp/request.json`
и получите выбранный маршрут:

```bash
curl --fail-with-body --max-time 190 -H 'Content-Type: application/json' \
  --data-binary @/tmp/request.json http://localhost:8080/v1/routes/generate \
  -o /tmp/generated.json
jq --slurpfile request /tmp/request.json \
  '{request:$request[0],base_place_ids:[.variants[0].stops[].place_id],change:{type:"remove",place_id:.variants[0].stops[0].place_id}}' \
  /tmp/generated.json > /tmp/recalculate.json
curl --fail-with-body --max-time 190 -H 'Content-Type: application/json' \
  --data-binary @/tmp/recalculate.json http://localhost:8080/v1/routes/recalculate
```

Для добавления используйте `change.type=add` и ID активного места, которого нет
в исходном списке и которое подходит категориям. Остальные параметры сохраните.
Каждый пересчёт использует свежие данные, поэтому `diff` сравнивает с заново
проверенным исходным порядком. Вызовы реального Mapbox расходуют квоту.

Каждый HTTP-запрос получает серверный `X-Request-ID`. Например, `curl -i` покажет
этот заголовок; по нему можно найти JSON-логи API (`docker compose --env-file backend/.env logs api`).
Запись `HTTP request` содержит request_id, method, шаблон path, status,
duration_ms и stage (validation/catalog/matrix/directions/planner/serialization).
Ошибки используют тот же ID. Клиентский X-Request-ID заменяется серверным.
Query-параметры, тела, координаты, токены и сырые ошибки провайдера не логируются.

### Ограничения запросов маршрутов

Генерация и пересчёт используют общий лимит в памяти одного процесса:

| Переменная | По умолчанию | Значение |
|---|---:|---|
| ROUTE_REQUESTS_PER_MINUTE | 6 | Скорость восстановления лимита на IP |
| ROUTE_BURST | 2 | Максимум накопленных запросов |
| ROUTE_MAX_CONCURRENT | 2 | Общий максимум выполняющихся расчётов |
| ROUTE_MAX_CLIENTS | 4096 | Максимум записей клиентов |
| ROUTE_CLIENT_TTL_SECONDS | 600 | Срок удаления неактивной записи |

Превышение возвращает 429 `rate_limited` и `Retry-After` в секундах. Очереди нет;
отказ из-за занятых слотов не расходует токен. Принятые некорректные запросы
тоже расходуют лимит. После HTTP-таймаута слот освобождается при фактическом
завершении обработчика. Каталог и health не ограничены этим лимитом.

IP берётся из RemoteAddr, X-Forwarded-For не используется. За reverse proxy
клиенты пока делят его IP-лимит; доверенные proxy требуют отдельной настройки.
TTL должен быть не меньше времени полного восстановления burst. Лимиты
передаются Compose и проверяются при запуске. Для нескольких экземпляров API
понадобится общее хранилище счётчиков; Redis в этом шаге не подключён.
