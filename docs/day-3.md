# День 3 — формат данных и импортёр

По календарю: 10 октября 2026. Реализовано и проверено 8 октября 2026.

## Результат

- Формат одного YAML на место описан в `data/README.md`.
- Строгий парсер отклоняет неизвестные поля, повторные ключи,
  несколько документов и повторные slug в наборе.
- Проверяются обязательные данные, координаты Минска, категории,
  важность, время осмотра, даты, расписание, исключения, цены и URL.
- Весь набор проверяется до записи. Места и связанные данные записываются
  одной транзакцией; ошибка не оставляет частичного импорта.
- Обновление по `(city_id, slug)` сохраняет ID и заменяет связанные сведения.
- Доступность ссылок проверяется после записи; ошибки дают предупреждения
  и не меняют успешный код выхода. Проверку можно отключить без сети.
- В рабочей БД 15 мест и 15 уникальных пар `(city_id, slug)` — больше
  требуемых для этого дня пяти тестовых карточек.

## Проверки

`TEST_DATABASE_DSN=... go test ./... -race -count=1 -timeout 60s` и
`go vet ./...` прошли на отдельной PostgreSQL-БД `vandrouka_test`.

Проверены повторный импорт без дублей, обновление с сохранением ID,
замена часов, откат при невалидных данных и при ошибке PostgreSQL.
Локальные HTTP-тесты покрывают перенаправления, HEAD → GET при 405/501,
404, 403, таймаут, отмену, дедупликацию URL и лимит одновременных запросов.

CLI с заведомо недоступным источником `http://127.0.0.1:1/unavailable`
завершился кодом 0 и сохранил тестовое место. Затем тестовая запись удалена.
Проверки не требуют удаления рабочей БД.
