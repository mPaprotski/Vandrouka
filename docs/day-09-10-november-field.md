день 10 нельзя считать выполненным без результатов поля и повторных проверок.

## 9 ноября: последовательность

1. Завершить внешний backend (Render/Neon/R2), применить миграции до 16.
2. Собрать самостоятельный preview APK и проверить подпись/чистую установку.
3. Выполнить preflight из корня:

```bash
python3 scripts/check_field_readiness.py --apk /path/to/vandrouka.apk --api-origin https://YOUR-API.onrender.com --online
```

Скрипт read-only, Mapbox/эмулятор не запускает. Проверяет preview-профиль,
HTTPS origin, структуру APK и подпись при наличии apksigner; --online вызывает
только health/catalog и auth-отказы приватных endpoint. Не проверяет встроенный
API URL внутри APK: это подтверждается телефоном. Без APK/API вернёт exit 2.

4. Скопировать field-report-template.md в отдельный отчёт с датой и SHA256 APK.
5. На свежем тестовом аккаунте пройти 3 точки пешком: Верхний город → внешний
осмотр Свято-Духова собора → Троицкое предместье. Это порядок из локального
каталога и состава коллекции, не проверенный навигационный маршрут.
Текущий общественный подход, переходы и доступность проверить на месте;
не заходить на закрытую территорию ради попадания в радиус.
6. У каждой точки: фото → GPS → upload → confirm → XP → история/фото → карта.
   Порог сервера 70 м, accuracy до 30 м; indoor/плохая точность не доказывают баг.
7. Повторить одну точку, проверить 0 XP; затем restart/offline/два аккаунта.
8. Записать подходы и фактические ограничения. Не помечать field_verified по
   одному прогону автоматических тестов или успешному открытию экрана.

Проверку можно репетировать в Expo Go, но её результат маркировать Expo Go:
она не доказывает самостоятельную работу APK без Metro. Не отключать GPS
проверки и не подменять координаты ради PASS. Нельзя имитировать поле эмулятором.
Открытие карты на телефоне расходует квоту Mapbox; агент её не запрашивает.

- Собрать новую тестовую версию и повторить исходный сценарий на телефоне.
- При возможности собрать короткую обратную связь 3–5 человек.
- Зафиксировать известные ограничения и подготовить повторный проход дня 11.

реализованы, но внешний запуск, backup по расписанию и ручное удаление остаются
отдельными открытыми проверками. Без результатов пользователя не выдумываем
полевые дефекты и не объявляем исправления проверенными на телефоне.
