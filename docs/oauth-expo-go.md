# Шаг 2 — проверка Google и Яндекса через браузер в Expo Go

Дата подготовки — 20 ноября 2026 года.

## Статус

Подготовлен диагностический прототип браузерного обмена. Он подключается к существующему API по флагу окружения либо запускается отдельной Go-командой и использует экран Expo Go `/auth-check`.

Прототип проверяет переход в системный браузер, callback на сервер, обмен кода у провайдера и получение результата исходным устройством. Успех означает подтверждение этой цепочки. Создание пользователя, связывание способов входа и выдача сессии Вандроўкі относятся к следующим этапам.

Автоматические тесты используют локальные заглушки. Реальная проверка Google, Яндекса и телефона ожидает регистрации OAuth-приложений, настройки публичного адреса прототипа и запуска на телефоне. Публикация нового кода и включение флага в Render выполняются перед реальной проверкой.

## Как проходит проверка

1. Expo Go генерирует случайный секрет устройства и передаёт серверу его SHA256.
2. Сервер создаёт попытку со сроком 5 минут и выдаёт адрес открытия браузера.
3. Браузер получает HttpOnly cookie и перенаправляется к выбранному провайдеру с `state` и PKCE S256.
4. Google или Яндекс возвращает код на фиксированный HTTPS callback сервера.
5. Сервер проверяет `state`, провайдера и cookie, обменивает код с PKCE, запрашивает идентификатор пользователя.
6. Браузер показывает предложение вернуться в Вандроўку.
7. Пользователь возвращается и нажимает «Проверить результат». Приложение передаёт секрет в JSON по HTTPS.
8. Сервер выдаёт итог только один раз. Токены и профиль провайдера в мобильное приложение не передаются.

Для Google прототип подтверждает личность через UserInfo с access token, полученным сервером при обмене кода. ID token в этой проверке не используется. Производственная интеграция и модель аккаунтов проектируются отдельно.

## 1. Подключить проверку к существующему API в Render

Пользователь выбрал существующий сервис `vandrouka-api`. В код API добавлено
условное подключение `/oauth/*` при `OAUTH_PROBE_ENABLED=true`. По умолчанию
проверка выключена. Отдельный сервис теперь нужен только при самостоятельном
использовании команды диагностики.

После публикации этих изменений в GitHub выполнить следующие действия.

1. Открыть Render → `vandrouka-api` → Environment.
2. В Linked Environment Groups подключить `vandrouka-oauth` с четырьмя параметрами Google и Яндекса.
3. Добавить `OAUTH_PROBE_ENABLED=true`.
4. Добавить `OAUTH_PROBE_ORIGIN=https://vandrouka-api.onrender.com`.
5. Сохранить настройки и развернуть коммит, содержащий подключение OAuth к основному API.
6. Дождаться Live и проверить `/health`.

Используются адреса возврата для провайдеров.

```text
https://vandrouka-api.onrender.com/oauth/callback/google
https://vandrouka-api.onrender.com/oauth/callback/yandex
```

Их нужно вписать в разрешённые redirect URI соответствующих OAuth-клиентов.
В примерах следующих разделов `https://AUTH-PROBE-HOST` обозначает
`https://vandrouka-api.onrender.com` для этого варианта запуска.

Переменная `OAUTH_PROBE_LISTEN` используется только отдельной командой
`cmd/oauth-probe`. Встроенная проверка обслуживается на штатном порту API.
После окончания диагностики отключить её через `OAUTH_PROBE_ENABLED=false`.

## 2. Создать приложение Google

1. Открыть [Google Cloud Console](https://console.cloud.google.com/).
2. Выбрать или создать проект для Вандроўкі.
3. Перейти в Google Auth Platform и заполнить Branding — название приложения и контактные адреса.
4. В Audience выбрать подходящую внешнюю аудиторию и на время проверки добавить свой Google-аккаунт в тестовые пользователи.
5. Настроить минимальные разрешения `openid` и `email`.
6. Создать OAuth Client типа Web application для серверного HTTPS callback.
7. В Authorized redirect URIs добавить точный адрес `https://AUTH-PROBE-HOST/oauth/callback/google`.
8. Сохранить Client ID и Client secret в переменные сервера `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`.
9. Если консоль требует подтверждение домена или дополнительных настроек публикации, выполнить их для фактического домена. Условия доступа для тестовых и внешних пользователей проверить в выбранном режиме Audience.

Если публичного адреса ещё нет, можно сначала подготовить проект и экран согласия. Финальный redirect URI добавить после определения адреса.

Тип клиента относится к серверному прототипу с HTTPS callback. Настройки нативного входа для Android/iOS определяются на этапе производственной интеграции.

## 3. Создать приложение Яндекс

1. Открыть [Яндекс OAuth](https://oauth.yandex.ru/).
2. Создать приложение для авторизации пользователей.
3. Указать название «Вандроўка» и контактные сведения.
4. Выбрать веб-платформу для серверного callback.
5. Добавить Redirect URI `https://AUTH-PROBE-HOST/oauth/callback/yandex`.
6. Выдать право получения email `login:email`. Идентификатор пользователя возвращается API Яндекс ID.
7. Сохранить Client ID и Client secret в переменные сервера `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`.
8. Убедиться, что данные приложения и режим доступа позволяют вход тестовым пользователям.

## 4. Сохранить конфигурацию

Для локальной команды можно использовать игнорируемый Git файл `backend/.env.oauth.local`.

```dotenv
OAUTH_PROBE_ORIGIN=https://AUTH-PROBE-HOST
OAUTH_PROBE_LISTEN=127.0.0.1:8082
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
YANDEX_CLIENT_ID=
YANDEX_CLIENT_SECRET=
```

Ограничить права файла для текущего пользователя. Команда читает переменные окружения, поэтому локальный файл нужно загрузить перед запуском.

```bash
cd backend
chmod 600 .env.oauth.local
set -a
source .env.oauth.local
set +a
go run ./cmd/oauth-probe
```

При локальном запуске публичный HTTPS-туннель должен направлять запросы на порт 8082. Параметры конкретного туннеля определяются выбранным сервисом.

На Render сохранить эти значения в Environment диагностического сервиса. Секреты провайдеров предназначены для сервера. Публичная конфигурация телефона содержит только origin прототипа.

## 5. Открыть проверку в Expo Go

1. Добавить в `mobile/.env.local` строку `EXPO_PUBLIC_OAUTH_PROBE_URL=https://AUTH-PROBE-HOST`.
2. Сохранить прежний `EXPO_PUBLIC_API_URL` для основного backend.
3. Перезапустить Metro с очисткой кэша.
4. Открыть приложение в Expo Go.
5. В профиле открыть страницу входа или регистрации.
6. Нажать «Проверить Google и Яндекс». Кнопка появляется в development-окружении при указанном origin прототипа.
7. На диагностическом экране выбрать Google.
8. Завершить вход в системном браузере.
9. После сообщения о завершении вернуться в Expo Go и нажать «Проверить результат».
10. Повторить для Яндекса.

Секрет попытки хранится в памяти устройства. После полного закрытия приложения или перезапуска сервера диагностики начать новую попытку. Одновременно хранится не более 128 попыток. Если ответ на выдачу итогового результата потерян, начать новую попытку. На этом этапе аккаунты и награды не создаются.

## 6. Что проверить вручную

- [ ] Google возвращается на правильный callback, приложение получает `success`.
- [ ] Яндекс возвращается на правильный callback, приложение получает `success`.
- [ ] Отмена на стороне провайдера отображается как отмена.
- [ ] После 5 минут попытка истекает и предлагается начать заново.
- [ ] После возвращения из браузера приложение сохраняет выбранную попытку.
- [ ] Сбой сети оставляет возможность запросить результат повторно, если он ещё не выдан.
- [ ] После закрытия Expo Go понятен запуск новой попытки.
- [ ] Неверный redirect URI даёт воспроизводимую ошибку настройки.

Записать версию Expo Go, ОС, браузер, провайдера и фактический результат. Только после такого прохода фиксируем совместимость на физическом устройстве.

## 7. Следующая интеграция

После подтверждения браузерного сценария добавить внешние идентификаторы к аккаунтам Вандроўкі, правила совпадения email, серверную выдачу существующей сессии, сохранение её в SecureStore и повторную авторизацию перед удалением аккаунта без пароля. Перенос краткоживущих попыток в устойчивое хранилище и восстановление после сбоев входят в производственный вариант.

## Серверный вход для мобильного приложения

Рабочий протокол использует основной API, миграции 21–22 и существующие сессии
«Вандроўкі». Для включения при выпуске задать `OAUTH_LOGIN_ENABLED=true` и
`OAUTH_LOGIN_ORIGIN=https://vandrouka-api.onrender.com`. Пары
`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` и
`YANDEX_CLIENT_ID` / `YANDEX_CLIENT_SECRET` читаются отдельно для каждого
провайдера. По умолчанию маршруты выключены. В консоли веб-клиента каждого
провайдера добавить соответствующий HTTPS callback:

- `https://vandrouka-api.onrender.com/v1/auth/oauth/callback/google`
- `https://vandrouka-api.onrender.com/v1/auth/oauth/callback/yandex`

Контракт мобильного клиента описан в `openapi.yaml`. Телефон сохраняет 32 случайных
байта в виде 64 строчных hex-символов и передаёт SHA-256 именно этой строки
в `POST /v1/auth/oauth/attempts`. Браузер открывает выданный URL, подтверждает
вход и возвращается по ссылке `vandrouka://auth-return?attempt=…&code=…`.
Срок попытки — пять минут. На завершение после callback отводится до минуты
в пределах исходного срока. Приложение предъявляет оба доказательства в
`POST /v1/auth/oauth/complete` и получает стандартный AuthSession. При потере
ответа на успешный обмен пользователь начинает новый вход с тем же провайдером.
Код `account_link_required` означает, что почта уже занята существующим профилем.
Диагностический экран Expo Go использует отдельные маршруты `/oauth/*`.
