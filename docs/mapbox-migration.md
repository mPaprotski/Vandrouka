# Решение: переход на Mapbox API

Принято 9 октября 2026 года по указанию владельца проекта. Решение заменяет
первоначальный план локальной Valhalla и собственных картографических тайлов.
Matrix/Directions реализованы и подключены к CLI; реальная проверка выполнена.

## Целевая архитектура

- Mapbox Matrix API, профиль `mapbox/walking`: направленная матрица времени
  и расстояний вместо Valhalla `sources_to_targets`.
- Mapbox Directions API, профиль `mapbox/walking`: геометрия, время,
  расстояния и инструкции итогового маршрута вместо Valhalla `/route`.
- Mapbox: подложка карты. Выбор отображения через MapLibre или Mapbox Maps SDK
  уточняется при интеграции мобильной карты с учётом совместимости стилей,
  условий использования и тарификации.
- Mapbox Geocoding API: поиск стартовой точки по адресу и обратное геокодирование.
- Mapbox Isochrone API: будущая область пешей доступности; функция пока не
  становится обязательной частью текущего MVP.

Наш Go API, PostgreSQL, каталог и planner остаются. Наш алгоритм выбирает места,
учитывает категории, расписания, стоимость, бюджет времени и темп, выполняет
greedy, 2-opt и swap. Mapbox предоставляет картографию и расчёт переходов.

Приложение обращается к Go API для планирования; Go API обращается к Mapbox
для Matrix/Directions/Geocoding. Карта загружает ресурсы Mapbox на устройстве.
Локальный сервер маршрутизации и сборка OSM-тайлов не требуются в целевой
архитектуре. До завершения миграции команды Valhalla остаются действующими.

## Задачи миграции

1. Разделить нейтральные типы маршрутизации и адаптер провайдера, сохранить
   интерфейс матрицы и тесты planner.
2. Добавить клиент Matrix/Directions: таймауты, ошибки, недостижимые пары,
   преобразование единиц и геометрии.
3. Разбивать большие матрицы с сохранением исходных индексов и направленности.
   Учесть лимит 25 координат для walking, а также лимиты Directions.
4. Добавить настройки токенов: серверный токен в переменных окружения,
   отдельный мобильный токен с нужными правами; токены не сохранять в Git.
5. Переключить CLI и backend. Темп применять один раз, проверить согласованность
   Matrix и Directions и соблюдение ограничений маршрута.
6. Настроить учёт запросов и элементов матрицы, допустимое кеширование согласно
   условиям Mapbox; уточнить тарифы перед внедрением.
7. На мобильном этапе подключить карту и геокодирование, настроить атрибуцию.
8. После сквозной проверки удалить Valhalla из Compose и активных инструкций.
   Исторические отчёты сохранить.

CI использует локальные HTTP-заглушки без токена и внешних вызовов. Реальная
проверка Mapbox проводится отдельно после настройки аккаунта и токена.

## Статус

Клиент Matrix/Directions реализован, CLI и routing-check переключены на Mapbox.
Матрицы разбиваются на блоки, длинные маршруты — на части с общим концом/началом.
Нейтральные типы маршрутизации выделены в отдельный файл; planner не зависит
от конкретного HTTP-клиента. Проверки идут на HTTP-заглушках и PostgreSQL.

Реальная проверка выполнена с токеном из локального игнорируемого `.env`.
Matrix, Directions и полный CLI работают. Valhalla удалена из активного
Compose; старый клиент, данные и инструкции сохранены как исторические.
Уже работающий контейнер Valhalla не останавливался; активный код к нему не обращается.
Кеширование пока не добавлено. Geocoding и карта остаются мобильным этапом,
Isochrone — последующим расширением. Детали: [Mapbox](mapbox.md).
