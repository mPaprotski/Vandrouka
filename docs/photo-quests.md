# Фотоквесты Вандроўкі

Зарегистрированный пользователь может создать маршрут из каталога и запустить его для группы. Каждый участник входит под своей учётной записью, вводит код запуска и указывает имя для списка группы. Организатор начинает прогулку, после чего участники получают первую подсказку и задание на фото.

## Редакции маршрута

- Шаблон привязан к городу, который выбирается при создании. Черновик можно сохранить до заполнения всех текстов.
- Для публикации нужны 2–20 разных действующих мест одного города и три текста на каждое задание: подсказка, задание для снимка и рассказ. Порядок задаёт массив заданий в запросе сохранения.
- Сохранение опубликованного шаблона переводит его в черновик новой редакции. Для новых запусков его публикуют снова. Созданный запуск хранит собственную копию порядка, мест, координат, адресов, ссылок и текстов.
- При редактировании, публикации, архивации, удалении и создании запуска сервер проверяет редакцию. Удалить можно только черновик без запусков. Архивация шаблона сохраняет его запуски.

## Присоединение и старт

- Код состоит из восьми символов и показывается при создании запуска или при замене. В базе хранится хеш. Сервер ограничивает подбор кода по аккаунту.
- До старта участник видит название и количество этапов. После старта получает идентификатор, номер, подсказку и задание текущего этапа. Полный маршрут, ответ и рассказ в эти данные не входят.
- Повторный вход по действующему коду возвращает прежнее прохождение. Замена кода и закрытие входа сохраняют существующих участников. Организатор видит их отображаемые имена и прогресс в своём запуске.
- Данные редактора и запуска доступны их автору. Участник может читать только собственное прохождение. Списки возвращаются страницами по 30 записей с непрозрачным указателем следующей страницы.

## Фото и прохождение

Участник создаёт попытку для текущего задания, загружает снимок и видит обработанный файл. Загрузка требует настроенного обработчика Deface. При недоступной обработке сервер возвращает ошибку и не сохраняет оригинал. Попытка не раскрывает место, адрес или рассказ.

При отправке сервер проверяет GPS. Ориентиры запуска составляют 70 м до точки, точность до 30 м, давность до 120 секунд и опережение времени до 30 секунд. Для согласованного повтора отправки используется заголовок `Idempotency-Key`. После успешной отправки сервер хранит время и показатели проверки без исходных координат.

Организатор видит очередь своего запуска. При отклонении он оставляет комментарий, участник может создать новую попытку. При принятии сервер в одной транзакции сохраняет посещение, начисляет +100 XP за первое подтверждённое посещение места и открывает рассказ и следующую подсказку. За уже открытое место начисляется 0 XP. После последнего этапа состояние становится `completed`. Повтор уже применённого решения возвращает результат, не начисляя XP повторно.

Черновики видит только участник. Организатор получает доступ к снимкам своего запуска после отправки. Снимок на проверке хранится до семи суток со дня отправки. После отклонения снимок хранится 24 часа. У неотправленного черновика есть 24 часа с начала загрузки. Отзыв черновика или работы на проверке закрывает доступ к снимку и передаёт файл в существующую очередь удаления. Удаление фото принятого посещения сохраняет рассказ, прогресс и XP.

## Мобильные экраны

Вкладка «Квесты» объединяет прохождения, запуски групп и шаблоны маршрутов. Автор выбирает места из каталога, редактирует и предварительно просматривает задания, публикует маршрут и выдаёт код группы. Во время прогулки он видит участников и очередь снимков. После завершения группа больше не может входить по коду или отправлять новые работы, а организатор ещё может проверить снимки в очереди.

Участник видит состояние этапа и проверенный снимок, после принятия читает рассказ и переходит к следующей подсказке. На финише показаны открытые места, время начала и завершения и суммарные XP.

Приложение проверяет статус ожидания на открытом экране каждые 6,5 секунды. При ошибках связи увеличивает интервал, а после возврата на экран обновляет статус сразу. Снимки для незавершённой загрузки остаются во временной папке приложения. Неопределённый результат отправки хранится в защищённом хранилище вместе с исходным ключом запроса и GPS. После перезапуска приложение сначала спрашивает состояние сервера, затем при необходимости повторяет тот же запрос.

## Доступ, сроки хранения и нагрузка

Файл доступен через приватный маршрут API. До отправки его видит только участник. Организатор получает доступ к отправленному снимку своего запуска и не получает доступ к обычной истории участника. В журналах остаются шаблон адреса и код ответа без пользовательских идентификаторов маршрута, кодов приглашения и содержимого фото.

По истечении срока API сразу перестаёт отдавать снимок. Работа исчезает из очереди, а участник видит истёкший срок и может переснять фото, пока прогулка открыта. Фоновый процесс помещает файл в очередь удаления. Если организатор удалил свой аккаунт, его запуски закрываются, незавершённые проверки прекращаются, а участники могут открыть ранее принятые точки и сохраняют XP. Удаление своего аккаунта удаляет личные прохождения и связанные снимки.

Обычная загрузка и квесты делят общий лимит операций с фотографиями. Deface обрабатывает по одному снимку на процесс. Повтор того же снимка использует уже загруженный результат. Если обработка ещё идёт или сервер занят, он сообщает, когда повторить запрос. Приложение сохраняет черновик на время ожидания.

Контракт серверных запросов описан в `openapi.yaml`, сценарий локальной и полевой приёмки — в `photo-quests-acceptance.md`.
