# День 26 — камера, геопозиция и приватный upload в Expo Go

Реализовано 20 октября 2026 года, досрочно по рабочему плану.
Последующее состояние: подтверждение, результат XP и защищённый журнал попытки добавлены [днём 27](day-27-mobile-confirmation.md).
Код и автоматические проверки готовы. Критерий плана «снимок загружается
на реальном телефоне» пока не подтверждён: физическая native-проверка ниже остаётся открытой.

## Поведение

Из карточки места кнопка **Сделать фото места** открывает `/capture/{id}`.
Гостю предлагается войти, загрузка использует текущую Bearer-сессию через общий
контроллер авторизации с обновлением access token. Другой аккаунт/место получает
отдельный черновик; поздние результаты старого не восстанавливают экран.

- Доступ к камере запрашивается кнопкой; при постоянном отказе доступны настройки.
  Задняя камера работает только на активном сфокусированном экране.
- Съёмка разрешена после `onCameraReady`; выбирается доступное разрешение до 4 MP.
  Если подходящего размера нет, показывается ошибка с повтором. JPEG снимается
  с quality 0.8, нормализацией ориентации и без выдачи EXIF/base64 в JS.
  Фактические файл/размер/геометрия проверяются до upload; окончательная проверка
  и удаление EXIF выполняются сервером.
- Есть локальный предпросмотр, пересъёмка и отмена. Галерея не используется,
  снимок остаётся в cache проекта.
- После **Загрузить фото** получается новый foreground GPS с `Accuracy.High`.
  Ожидание до 30 с; неизвестная точность и accuracy >30 м пропускаются до лучшей
  фиксации/таймаута. Принимаются фиксации не старше 30 с и не более 5 с в будущем.
  Ошибки разрешения, выключенный GPS и таймаут возвращают к предпросмотру.
  Порог 50 м и итоговый возраст GPS проверяет backend при confirm днём 27.
- Multipart содержит только `place_id` и `file`, без GPS, client owner или XP.
  `Content-Type` с boundary задаёт React Native; Bearer идёт только в заголовке.
  Таймаут клиента 60 с; HTTP-ошибки показывают сообщение и Request ID.
  При ошибке снимок сохраняется для явного retry, автоматических повторов upload нет,
  кроме повторения после 401 с обновлённым токеном общим session controller.
- Пока выполняется операция, второй upload не запускается. Уход в фон, blur
  и отмена останавливают watcher/запрос; поздние результаты игнорируются.
  Снимок сохраняется в текущем черновике для повтора. Камера размонтируется.
- При пересъёмке/закрытии экрана локальное фото удаляется, известный private upload
  удаляется по API. Если ответ потерян или удаление невозможно, работает TTL backend:
  15 минут для uploading, 24 часа для ready без confirmed visit.
  Черновик не сохраняется на диск и не восстанавливается после restart.

Успех пока означает **«Фото загружено»**, а не confirmed visit. Экран явно сообщает,
что XP не начислен. Отправка `POST /v1/places/{id}/visits`, повторная актуализация GPS
после длительного upload и экран результата — день 27. Нельзя использовать старую
фиксацию автоматически для будущего confirm.

## Совместимость

Установлены `expo-camera ~57.0.6` и `expo-file-system ~57.0.7` через `expo install`.
Используется `CameraView` SDK 57 и поддерживаемый `expo-file-system/legacy`
для getInfo/delete cache-файла. Native transport — стандартный FormData React Native
с `{uri, name, type}`. Нативные директории не создавались.

Официальные документы SDK 57 подтверждают включение модулей в Expo Go:
[Camera](https://docs.expo.dev/versions/v57.0.0/sdk/camera/),
[FileSystem legacy](https://docs.expo.dev/versions/v57.0.0/sdk/filesystem-legacy/),
[Location](https://docs.expo.dev/versions/v57.0.0/sdk/location/).
Camera config plugin не добавляет запись аудио; разрешения микрофона,
галереи и background location приложение не запрашивает.

## Автоматические проверки

- `npm test`: все 9 файлов тестов прошли. Добавлены проверки выбора разрешения,
  свежести/accuracy, multipart/заголовков, проверки ответа, размера, timeout/abort,
  двойного upload, ошибок, отмены, очистки и поздних результатов после закрытия.

- `EXPO_OFFLINE=1 npx expo install --check` — версии соответствуют локальной карте SDK;
  offline-проверка не является проверкой актуальности registry.
- Android export без сети/эмулятора: `/tmp/vandrouka-day26-export`, Hermes bundle 2.9 MB.
- Реальные mobile API client + session/photo controllers проверены с локальными
  API/PostgreSQL/MinIO: регистрация, JPEG multipart upload, decode ready,
  приватное чтение и удаление (последующее чтение 404). Тестовый аккаунт удалён.
  В этом smoke нативные камера/GPS заменены фиксированными данными, а file URI
  адаптирован в Node FormData; это не проверка Android bridge и разрешений.

## Проверить на физическом телефоне

1. Убедиться, что API и приватный MinIO работают. Перезапустить Metro после установки
   зависимостей: `cd mobile && npm start -- --clear`. Открыть проект в Expo Go.
2. Войти → список мест → карточка → **Сделать фото места**. Начать из списка,
   чтобы эта проверка не загружала карту и не расходовала Mapbox-квоту.
3. Отказать в камере: приложение остаётся рабочим. Затем разрешить камеру;
   при постоянном отказе перейти в настройки, разрешить и вернуться.
4. Сделать снимок: проверить ориентацию и предпросмотр. Переснять, отменить,
   вернуться из карточки повторно. Проверить отсутствие фото в галерее.
5. На открытом месте нажать **Загрузить фото**, разрешить foreground GPS.
   Дождаться **Фото загружено**. На первом системном запросе разрешений операция
   может прерваться при переходе приложения в inactive; после возврата повторить.
6. Отключить GPS/запретить геолокацию: upload не начинается, снимок остаётся.
   С плохой accuracy дождаться понятного таймаута; включить точную геолокацию
   в системных настройках и повторить.
7. При upload выключить сеть/свернуть приложение/отменить; проверить возврат
   к предпросмотру и успешный явный retry. Быстрые двойные нажатия не дают два upload.
8. Уйти назад во время съёмки/GPS/upload; поздний ответ не должен открыть экран
   успеха или восстановить закрытый черновик. Проверить выход и смену аккаунта.
9. Учесть: посещение и XP этот экран пока не создаёт; это следующий этап.

Результаты на CMF Phone 2 ещё не записаны. До этой проверки нельзя считать весь
день 26 закрытым по критерию приёмки. Коммит и push не выполнялись.
