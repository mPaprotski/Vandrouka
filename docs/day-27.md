# Этап 27 октября — генерация маршрутов через HTTP

## Пункт 1: HTTP-модели — выполнен

Запросы и ответы по OpenAPI отделены от моделей Planner. Транспорт использует
snake_case, дробные секунды и метры, целые копейки BYN. Обязательные коллекции
сериализуются как []/{}, отсутствующая геометрия — null. Указатели в запросе
сохраняют отсутствие значений, явные false/0 и неограниченный бюджет билетов.
Общий APIError используется существующими обработчиками каталога.
Коммит: `19ef473` — `Add HTTP models for route generation contract`.

## Пункт 2: разбор и валидация — выполнен

`ReadGenerateRouteRequest` проверяет Content-Type и вызывает чистый парсер.
Неверный запрос получает 400 с общим форматом `invalid_request`; успешное чтение
ещё не отправляет ответ. Новый POST пока не зарегистрирован: подключение
HTTP-обработчика предусмотрено пунктом 7.

Тело — один объект JSON UTF-8, максимум 64 КиБ. Отклоняются неизвестные поля,
повторные ключи (в том числе внутри start), дополнительные JSON-документы,
неверные типы и null вне nullable ticket_budget_minor. Имена полей имеют
точный регистр по OpenAPI. Content-Type application/json допускает charset.

Обязательны start с lat/lon, start_at с часовым смещением и бюджет времени.
Проверяются мировые координаты, а для Минска — прямоугольник импорта
53.75–54.05 N / 27.3–27.85 E. Это область поддержки, не административный полигон.
Лимит времени 1–1440 минут, темпы slow/normal/fast, шесть известных категорий
без повторов, неотрицательные целые копейки BYN и seed 0–9007199254740991.

Значения по умолчанию: minsk, normal, seed 42, все категории, geometry=true.
Явные seed=0 и geometry=false сохраняются. Отсутствие/null бюджета билетов
означает без лимита, указанный 0 — нулевой лимит. Данные запроса копируются,
чтобы последующее изменение нормализованного результата не меняло исходную DTO.

Время Минска переводится в Europe/Minsk, включая смену местной даты.
IANA-база встроена через time/tzdata: минимальный Docker-образ не требует
установленной системной базы часовых поясов.
Допускаются RFC3339 t/z в нижнем регистре. Для синтаксически корректного иного
slug поиск города отложен в сервис (пункт 3), где возможен 404. После поиска
`InCityTimezone` переводит время по IANA timezone из метаданных города.
Парсер и валидатор не обращаются к PostgreSQL или Mapbox.

Тесты проверяют границы, значения по умолчанию, дробные копейки и переполнение,
повторные поля, повреждённый UTF-8, дополнительный документ, ошибки чтения,
нулевой бюджет, неизвестный город и HTTP-ответы 400. Сетевые вызовы и генерация
маршрутов остаются следующими пунктами плана.

Коммит пункта 2: `Validate route generation requests and apply defaults`.

## Пункт 3: сервис и подготовка каталога — выполнен

Пакет `internal/routes` отделён от HTTP, имеет интерфейс Catalog и сервис
`Prepare`. Репозиторий реализует `ListActivePlaces` через существующий запрос
с `p.is_active`; рабочие GET и схема БД не изменены. Тест с PostgreSQL проверяет,
что выключенное место отсутствует в карточках, моделях Planner и индексах матрицы.

Сервис сначала находит город, получает его IANA timezone и переводит стартовое
время. Неизвестный город — `ErrCityNotFound` для будущего HTTP-ответа 404;
ошибки репозитория сохраняются через wrapping, отмена контекста учитывается.
Пустой или неправильный серверный timezone отклоняется как ошибка данных.

Активные места загружаются один раз в стабильном порядке репозитория.
Выбор нескольких категорий означает объединение: место с хотя бы одной
выбранной категорией включается один раз. Пустой список означает все категории.
Дубликаты ID обрабатываются по правилу Planner: первая запись выигрывает,
в том числе до фильтрации категорий. Записи с неправильным ID/городом отклоняются.

`Prepared` содержит City, запрос Planner, выбранные места, исходные карточки
по PlaceID и соответствие ID → индекс матрицы. Индекс 0 зарезервирован для
старта, места имеют индексы 1..N. Цена взрослого билета переводится в копейки
существующим `FromCatalogPlace`, сохраняются расписания и исключения.
Подготовленные массивы и указатели не меняют данные запроса/репозитория.

Пустой набор возвращается без ошибки, с пустыми коллекциями и `Empty()=true`.
В будущем Generate сможет выдать `variants: []` без вызова Mapbox. Сейчас
`Prepare` только подготавливает данные: Matrix, PlanVariants и выдача HTTP
будут подключены следующими пунктами. Сервисные тесты работают без БД и сети.

Коммит пункта 3: `Add route generation service with catalog dependencies`.

## Пункт 4: Matrix и Planner — выполнен

Сервис получает зависимости через `WithMatrixBuilder` и `WithVariantPlanner`;
по умолчанию используется существующий Planner, настройки весов можно внедрить.
Для Mapbox подключается `planner.NewRouterMatrixBuilder(mapboxClient)`.
`GenerateCandidates` вызывает Prepare, строит одну направленную матрицу
и передаёт её в PlanVariants с включённой оптимизацией. Шесть кандидатов
используют одну матрицу; возвращается не более трёх различных вариантов.

Результат сохраняет карточки, индексы и матрицу для следующей проверки Directions.
Это предварительные варианты, они ещё не выдаются через HTTP как окончательные.
При пустом каталоге возвращается пустой список без обращения к Matrix.
Ошибки маршрутизатора обозначаются ErrRoutingUnavailable; отмена контекста
останавливает переход к следующему этапу. Ошибки Planner не скрываются.

Адаптер теперь проверяет размер матрицы N×N: отсутствующие строки/столбцы
раньше могли интерпретироваться как недостижимые переходы и пустой успешный
маршрут. Неполная матрица теперь даёт ошибку до вызова Planner.

Сервис проверен через существующий routing-адаптер с подставным провайдером:
индекс 0 — старт, далее только выбранные места в стабильном порядке.
Ручной направленный пример: ходьба 6+4 минут, осмотры 10+15, итог 35 минут,
0.75 км и 250 копеек BYN. Обратный переход длиннее; закрытая и недостижимая
точки не включаются. Проверены slow/normal/fast (37/35/33.5 минуты),
точные лимиты времени/билетов и повторяемость результата с seed 42.
Дополнительно используется независимый аудитор этапа 25 октября.
Тесты работают без PostgreSQL, Mapbox-токена и внешней сети.

Коммит пункта 4: `Generate route variants using Mapbox Matrix and Planner`.

## Пункт 5: проверка Directions — выполнен

`Service.Generate` выполняет подготовку, Matrix/PlanVariants и обязательную
проверку каждого кандидата через внедрённый интерфейс Directions. Провайдер
получает старт и остановки в их порядке; обратный переход к старту не добавляется.
Отключённая выдача геометрии не отключает проверку Directions. Отсутствие
зависимостей проверки обнаруживается до платного Matrix-вызова.

Каждый результат содержит отдельную подтверждённую матрицу: выбранные переходы
заменены данными Directions, остальные переходы и исходная матрица не изменены.
`EvaluateOrder` пересчитывает весь маршрут, прибытия, уходы, бюджет, расписания,
расстояние и стоимость. При настройке весов используется тот же Planner для
генерации и проверки; их значения не сбрасываются на значения по умолчанию.
Суммарные duration/distance провайдера не подменяют сумму выбранных legs.

NoRoute, недостижимость и ErrInfeasible отбрасывают только соответствующий
вариант. Если все варианты отброшены, возвращается успешный пустой список.
Ошибки сервиса, повреждённые legs/геометрия и ограничения частоты — ошибка
ErrRoutingUnavailable для будущего ответа 503, а не пустая успешная генерация.
Отмена контекста прекращает дальнейшую проверку.

После проверки варианты сортируются по окончательному Score; матрица и формы
остаются связанными со своим вариантом. Метки назначаются заново только среди
выживших вариантов, у единственного варианта сравнительные метки удаляются.
Геометрия копируется для выдачи, либо отсутствует при include_geometry=false.

Тесты без сети подтверждают пересчёт дробных секунд и расстояния, превышение
бюджета на микросекунду, закрытие во время осмотра, NoRoute, недостижимость,
некорректный ответ, отмену запроса, сохранение весов, окончательное ранжирование
и метки после удаления вариантов. HTTP-сериализация и регистрация обработчика
остаются пунктами 6–7; реальные Mapbox-вызовы на этом пункте не выполнялись.

Коммит пункта 5: `Verify generated routes against Mapbox Directions`.

## Пункт 6: окончательный HTTP-ответ — выполнен

`BuildGenerateRouteResponse` преобразует только итоговый Result сервиса,
а не Matrix-кандидаты. Карточки дают имя/координаты; подтверждённая матрица
и timestamps дают переходы, время осмотра, arrival/departure и totals.
Индексы сохраняют направление от старта, затем от предыдущей остановки;
возврат к старту не добавляется. Времена выводятся в timezone города.

Точные секунды и метры не округляются вниз. Суммы вычисляются по остановкам
и подтверждённым переходам и сверяются с метриками Planner. Для сверки
плавающих метрик используется допуск 1e-7, но бюджет времени проверяется
по целому time.Duration, стоимость — по целым копейкам без допуска.
Превышения бюджетов, неверные ID, повторы, неправильные времена, признаки
неопределённости или противоречивые totals приводят к ошибке сериализации,
а не выдаче некорректного маршрута.

Вариант получает ID variant-N в рамках ответа, профиль и окончательные метки.
Для единственного варианта сравнительные метки недопустимы. Explanation
использует существующий текст Planner и отдельно возвращает число неизвестных
часов/цен и распределение категорий. Пересечение категорий сохраняется.
`cost_complete=false` при любой неизвестной цене; cost_minor — только известная
часть. Остановка с неизвестными часами и ценой считается один раз в unverified.

Геометрия — копия упорядоченных polyline6-сегментов либо null. Пустой результат
сериализуется как variants: []. Сериализация не меняет данные сервиса.
HTTP-обработчик ещё не зарегистрирован — это следующий пункт.

Тест с независимо рассчитанными ожиданиями: 422.3579 секунды ходьбы,
1500 секунд осмотра, итог 1922.3579, расстояние 600 метров, известная стоимость
150 копеек и одна остановка с неизвестными часами/ценой. Проверены fast,
выключенная геометрия, полный известный бюджет, пустой ответ и повреждённые данные.
Go-тест может записать действительный JSON через ROUTE_RESPONSE_EXAMPLES_DIR;
`check_openapi.py --route-response <file>` проверяет его по схеме ответа.
Такая проверка добавлена в backend job CI, вместе с существующими примерами.

Коммит пункта 6: `Serialize verified route variants with totals and explanations`.
