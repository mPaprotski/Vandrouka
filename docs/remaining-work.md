# Вандроўка — оставшиеся работы

Актуализировано 23 ноября 2026 года. Тесты приложения, приёмка на телефоне и общий деплой запланированы после завершения разработки.

Документ объединяет незавершённую приёмку MVP, новые требования к карточкам и дальнейшее развитие продукта. Новые календарные сроки пока не согласованы. Прежний срок MVP — 15 ноября 2026 года. Фактическое завершение релиза нужно зафиксировать после приёмки.

Галочка означает подтверждённый результат. Наличие кода само по себе не закрывает проверку на телефоне. Задачи следующих этапов не становятся обязательными для текущего MVP без отдельного решения.

## 1. Исходное состояние

Основной игровой функционал реализован. Есть каталог 60 мест Минска, карта и карточки, регистрация и вход, фотографирование, приватная загрузка фото, GPS-подтверждение, XP и уровни, история, личная карта, удаление данных, три достижения и одна коллекция.

Серверный планировщик, CLI, генерация и пересчёт маршрутов существуют. Мобильный интерфейс планировщика предстоит реализовать.

Внешнее окружение было развёрнуто и проверено ранее. Его текущую доступность нужно повторно подтвердить перед приёмкой.

| Компонент | Подготовлено |
|---|---|
| Backend | Render, `https://vandrouka-api.onrender.com` |
| База данных | Neon, PostgreSQL, миграции до версии 16, каталог 60 мест |
| Приватные фотографии | Backblaze B2, бакет `vandrouka-visit-photos` |
| Карта | Mapbox через WebView |
| Приложение | Expo, самостоятельный Android APK 0.1.0 (1) |
| Последний отправленный коммит | `891d2ba`, документация |
| Исходники готового APK | `30cb47c` |

[Готовая сборка APK в Expo](https://expo.dev/accounts/mpaprotskis-team/projects/vandrouka/builds/1061ef17-6b37-447b-8d18-0efbb83211db).

Дальнейшие локальные изменения карточек в этот APK не входят.

## 3. Резервные копии и эксплуатация

Локальный backup/restore проверялся. Полноценное восстановление внешних Neon и B2 ещё требует реализации и проверки. Локальная копия в `/tmp` не обеспечивает постоянное хранение.

- [ ] Согласовать независимое место хранения резервных копий.
- [ ] Согласовать периодичность копирования и срок хранения.
- [ ] Подготовить резервное копирование Neon и связанных приватных фотографий B2.
- [ ] Обеспечить согласованность снимка БД и набора файлов при продолжающихся загрузках и удалениях.
- [ ] Настроить запуск по расписанию и уведомление об ошибке копирования.
- [ ] Восстановить копию в изолированное окружение, содержащее тестовое посещение и фотографию.
- [ ] Прочитать восстановленную фотографию через приложение/API с проверкой владельца.
- [ ] Описать восстановление с учётом отзыва сессий и удалений, произошедших после создания копии.
- [ ] Зафиксировать порядок проверки health, просмотра логов, ручного развёртывания и отката версии backend.
- [ ] Перед выпуском пересмотреть известные предупреждения зависимостей Expo и применимость к используемой версии.

Redis сейчас не является зависимостью MVP. Общее хранилище лимитов и состояние нескольких экземпляров backend рассматриваются при переходе к масштабированию.

## 4. Карточки мест

В коде готовы краткие описания, адреса и источники для 60 мест Минска.
Адрес открывает точку в совместимом приложении карт Android с резервной веб-ссылкой.
Для парков, площадей и отдельных объектов комплекса используются ориентиры.
При отсутствии адреса доступна кнопка открытия точки на карте.
Атрибуция фотографий сохранена.

На финальную приёмку перенесены:

- [ ] Проверить номера домов и входы на месте, особенно для комплексов с несколькими объектами.

- [ ] Прогнать серверные и мобильные проверки и включить карточки в общий выпуск.

## 6. Авторские маршруты-квесты для учителей и других организаторов

Новая согласованная продуктовая идея. Реализация ещё не начата.

Участник получает подсказку к первой точке, находит место, делает фотографию и проходит проверку. После принятия задания открываются краткая информация о месте и подсказка к следующей точке. Цепочка повторяется до завершения квеста.

### 6.1. Первая версия

Маршрут может создать зарегистрированный пользователь. Организатор выбирает точки каталога, публикует маршрут и выдаёт группе код. Каждый участник проходит задания отдельно через свой аккаунт. Сервер проверяет GPS, организатор проверяет содержимое обработанного снимка. Принятое задание засчитывается как обычное посещение. Первое открытие приносит 100 XP, повторное — 0 XP. Дополнительной награды за квест нет.

У каждого запуска своя копия заданий. Автор может закончить прогулку в любой момент после старта. Уже отправленные работы можно проверить после закрытия, а новые отправки закрываются.

### 6.2. Реализовано

- [x] Шаблон, редактор с упорядоченными заданиями, предпросмотр и публикация.
- [x] Запуски по коду, ожидание старта, раздельный прогресс и скрытие следующих точек.
- [x] Обработка фото, проверка GPS, очередь организатора, отклонение с комментарием и повтор.
- [x] Рассказы после принятия, результат прохождения, обычные посещения и однократное начисление XP.
- [x] Сохранение локального черновика и повтор отправки после потери ответа.
- [x] Приватный доступ, сроки хранения снимков и сохранение прогресса участников после удаления организатора.

### 6.3. Осталось

- [ ] Пройти сценарий на физических телефонах и провести пилот с организатором и группой.
- [ ] Проверить нагрузку на выбранном внешнем сервере и обработку реальных снимков на прогулке.
