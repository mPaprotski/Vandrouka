## Пункт 2: навигация

- Корневой Stack: приветствие → вкладки → отдельная карточка `/places/[id]`.
- На приветствии добавлена ссылка «Начать прогулку». Она заменяет приветствие
  в истории: системная кнопка назад не возвращает к нему после входа во вкладки.
- Три вкладки: `/explore`, `/visits`, `/profile`. Возврат из других вкладок
  ведёт в «Исследовать» (`backBehavior=initialRoute`).
- В исследовании доступен явно обозначенный локальный пример «Минская ратуша».
  Это ссылка для проверки навигации, не загруженный серверный каталог.
- Карточка открывается поверх вкладок; назад возвращает в предыдущий экран.
  Для входа по прямой ссылке кнопка назад предусматривает переход к исследованию.
  Неизвестный ID показывает понятное сообщение без вымышленных данных.
- Профиль и посещения содержат пустые состояния. Вход, XP и сохранение посещений
  пока не подключены. Нижние вкладки на карточке скрыты.
- Цвета и оформление продолжают стиль стартового экрана. Контент прокручивается,
  нижние safe area обрабатываются навигатором, карточка имеет заголовок и назад.

Новых зависимостей и запросов к backend/Mapbox нет.
Пункт 6 (сквозная проверка на телефоне) ещё не завершён.
Доступ к health с телефона остаётся непроверенным критерием пункта 4. Коммит и push не выполнялись.

## Пункт 3: общие компоненты

Добавлены `src/components/ui/`:

- `AppButton`: основной/вторичный вид, нажатие, disabled и loading.
  Во время загрузки кнопка блокирует повторное нажатие; accessibilityState
  сообщает busy/disabled и состояние раскрытия подсказок.
- `LoadingState`: индикатор и настраиваемая подпись без фиктивных задержек.
- `ErrorState`: сообщение, callback повтора, блокировка кнопки при retrying,
  необязательный Request ID («Код обращения») для поддержки.
- `EmptyState`: заголовок, пояснение и необязательное действие.
- `PlaceCard`: название, необязательные категории/описание, открытие по нажатию.
- `theme`: общие цвета текущего оформления.

Кнопка подключена к подсказкам, возврату из карточки и пустым состояниям.
PlaceCard используется для локального примера ратуши. Профиль, посещения и
неизвестное место используют EmptyState. Состояния загрузки и ошибок пока
не показываются: их подключит API-клиент следующего этапа. Сетевые запросы,
новые зависимости, эмулятор и нативная сборка не требовались.

Проверка на телефоне: открыть карточку, нажать «Исследовать город» из профиля
и посещений, раскрыть/скрыть подсказки; проверить крупный системный шрифт.
Loading/Error будут проверены вместе с реальными запросами и их отказами.

## Пункт 4: адрес backend

Добавлен `src/config/api.ts`: чтение EXPO_PUBLIC_API_URL, USB default
http://127.0.0.1:8080, проверка корневого HTTP(S)-адреса и нормализация.
Пустая/неправильная конфигурация возвращает ApiConfigurationError без исходного
значения в сообщении. Пути, credentials, query и fragment не принимаются.
Создан игнорируемый `.env.local` с USB-default; существующий файл не перезаписывается.
Пример больше не использует адрес эмулятора 10.0.2.2.

Backend уже слушает :8080 на всех интерфейсах, Compose публикует 8080:8080.
Изменять сервер для доступа по USB/Wi-Fi не потребовалось. Инструкции в mobile/README
разделяют Metro (8081) и API (8080), описывают adb reverse, LAN IP и health через браузер.

Добавлены независимые от сети проверки адресов USB/LAN/HTTPS/IPv6, некорректных
значений, секретов в URL и чтения env (`npm test`, без новых зависимостей).
API-клиент подключит конфигурацию в следующем пункте. Сам health из приложения
ещё не вызывается. Достижимость backend с физического телефона не подтверждена;
это остаётся частью последующей сквозной проверки. Эмулятор/Mapbox не использовались.

## Пункт 5: API-клиент и реальные данные

Добавлены типизированные методы для пяти существующих серверных API.
Сверены обёртки cities/categories/places, отдельный объект карточки, числовой ID,
APIError и заголовок X-Request-ID. JSON проверяется во время выполнения: нужные
строковые/числовые поля, координаты, массивы, безопасные положительные ID.
Неожиданный ответ не подменяется пустым результатом.

Общий запрос имеет таймаут 10 секунд (включая response.json), AbortSignal,
различает HTTP/сеть/таймаут/отмену/ошибку формата. APIError хранит status/code/
Request ID. Неуспешный HTML-ответ и сетевые исключения дают безопасные сообщения.
Конфигурация читается через getApiBaseUrl без падения при импорте модуля.

Раздел исследования запрашивает места и категории Минска; карточка — выбранное
место и категории его города. Локальный пример ратуши удалён. При уходе/смене ID
запрос отменяется, запоздалый результат игнорируется; при возврате загрузка
повторяется. Пустой список, ошибка и повтор используют компоненты пункта 3.
Профиль/посещения не изменялись, карта ещё не подключена.

Тесты без сети покрывают пять методов, URL/query, пустой каталог, повреждённый
JSON/поля/координаты, несовпадающий ID, HTTP APIError/Request ID, HTML-ошибку,
недоступность БД через health=503, сеть, таймаут fetch и тела ответа, отмену
и уже отменённый сигнал, недопустимые ID/slug. Новых зависимостей нет.

Локальный /health на 127.0.0.1:8080 недоступен (connection refused): сервер
не запущен на этом порту. Это не подтверждает сквозную работу клиента с backend.
Физический телефон, Android Back, сворачивание и восстановление сети относятся
к оставшемуся пункту 6. Эмулятор не запускался, Mapbox API не вызывался.

Итог пункта 5: npm test, TypeScript, ESLint и офлайн-экспорт Android проходят;
git diff --check без ошибок. Проверки hook lifecycle на телефоне ещё не выполнены.
