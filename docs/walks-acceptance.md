# Планировщик прогулок — приёмка

## Реализованное поведение

- Построение вариантов, расписание остановок, карта и изменение состава через серверный пересчёт.
- Начало, пауза, продолжение, завершение и восстановление снимка прогулки после перезапуска.
- Одна незавершённая прогулка на аккаунт и адрес API на устройстве. Гости могут планировать, для личного прохождения нужен вход.
- Снимок и геометрия сохраняются в documentDirectory. Две чередующиеся записи позволяют восстановить предыдущую целую версию после прерванной записи.
- Подтверждённый визит засчитывается при 100 и 0 XP. Попытка хранит walkId. Прогресс записывается до очистки ключа подтверждения.
- Обычный визит в точку активной прогулки также связывается с ней перед отправкой подтверждения.
- Удаление аккаунта очищает его локальные прогулки. Смена аккаунта открывает собственное хранилище.
- max_distance_m, max_stops, travel_mode применяются при генерации, оптимизации и пересчёте. Финальная дистанция проверяется после Directions.
- Матрица и Directions используют выбранный профиль walking/cycling в контексте запроса. Темп ходьбы применяется к walking.

## Проверка на телефоне перед выпуском

1. Построить прогулку по Минску на 90 минут, сравнить варианты, открыть место и вернуться к тому же расчёту.
2. Удалить остановку, проверить разницу, отменить предложение. Повторить и применить. Добавить другую точку.
3. Проверить линию, номера, обзор всего маршрута, ручной переход к GPS. При отключении подложки открыть список.
4. Начать прогулку, подтвердить посещение с 100 XP. Повторить сценарий с ранее посещённым местом и 0 XP.
5. Прервать сеть после отправки визита, перезапустить приложение, повторить проверку результата. Остановка засчитывается один раз.
6. Поставить на паузу, закрыть и открыть приложение. Продолжить и проверить сохранённое активное время.
7. Сменить аккаунт и убедиться, что чужая прогулка не отображается. Вернуться в исходный аккаунт.
8. Завершить неполную и полностью пройденную прогулки. В итогах проверить подтверждённые места, время и плановую длину.
9. Построить пеший и велосипедный варианты с лимитом расстояния и числа мест. Проверить ограничения после изменения состава.

## Условия выпуска

Телефон через ADB при последней проверке не подключён. Полевая приёмка остаётся открытой.

Публиковать сначала backend с поддержкой новых полей, затем совместимую мобильную сборку. Старый опубликованный backend отклоняет неизвестные поля запроса. В текущей сессии доступ к Render API не настроен. Новая версия backend и APK с этими изменениями ещё не опубликованы.
