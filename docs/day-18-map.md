# Этап 18 октября — карта через Expo Go WebView

Реализовано 19 октября 2026. Способ согласован пользователем: Mapbox GL JS
в react-native-webview, без нативного Mapbox SDK и без запуска эмулятора.

## Реализация

- Установлен react-native-webview 13.16.1 через expo install для SDK 57.
- Минск: центр [27.5615, 53.9023], zoom 12, Streets v12, GL JS 3.33.0.
- HTML создаётся локально; библиотека/стили/тайлы загружаются с Mapbox по HTTPS.
- Координаты [lon, lat], маркеры из backend; выбор передаёт только известный ID.
- Данные передаются через безопасную сериализацию, имена не вставляются как HTML.
- Native-bridge принимает только ready/error/select, проверяет ID по каталогу,
  ограничивает размер сообщения; произвольные URL/действия не выполняются.
- Навигация WebView ограничена: внешние ссылки атрибуции открываются в браузере
  только для разрешённых HTTPS-доменов. Логотип и атрибуция не скрываются.
- Сохранён список с FlatList. Без pk-токена карта не создаётся; список доступен.
- Ошибки WebGL/загрузки/авторизации, остановка WebView и таймаут 30 секунд дают
  понятное сообщение, ручной повтор и переход к списку. Сырые ошибки с URL/token
  из Mapbox не выводятся пользователю и не передаются в native-bridge.
- WebView сохраняется при переключении режимов/возврате из карточки, source
  стабилен, данные обновляются через JS. useApiResource сохраняет последний
  успешный каталог при повторной загрузке; старые данные обозначаются в UI.
- Пустой каталог показывает EmptyState, ошибка backend — ErrorState/повтор.

## Конфигурация и ограничения

Нужен EXPO_PUBLIC_MAPBOX_ACCESS_TOKEN=pk.… в mobile/.env.local, отдельный от
секретного backend sk-токена. Пользователь добавил публичный токен в локальный env. Серверный секрет
не переносился.
Для доменных URL-ограничений следует учитывать origin inline WebView.
Открытие/перезагрузка настоящей карты расходует Mapbox-квоту; автоповторов нет.
Реальные запросы Mapbox разрешены пользователем. Выполнен ровно один GET
к Streets v12 с публичным токеном: HTTP 200, style version 8, один source и
134 слоя. Токен не выводился, тайлы/шрифты/маршруты не запрашивались.
Это подтверждает доступность стиля, но не рендеринг WebGL в Expo Go. Геолокация, маршруты и профиль не входят
в этот этап. Работа WebGL и жестов на реальном CMF Phone 2 ещё не подтверждена.

## Проверки

Тесты без сети проверяют публичный токен, безопасный script JSON, bridge,
запуск HTML с фиктивным Mapbox/DOM, центр и порядок координат, создание/удаление
маркеров, выбор ID, пустой набор и код ошибки авторизации без утечки сообщения.
Экспериментальная VM-проверка не заменяет Android WebView/WebGL E2E.
Expo Doctor: 21/21. npm audit после установки: 28 предупреждений (10 moderate,
18 high), как до установки; принудительная смена SDK не выполнялась.

Итог: npm test, TypeScript, ESLint, git diff --check и офлайн-экспорт Android
(1260 модулей) прошли. Живая карта и Android WebGL на телефоне пока не проверены.
Коммит/push не выполнялись.

После подтверждения пользователя публичный токен проверен одним запросом;
для завершения этапа нужна проверка карты/маркеров на физическом телефоне.

## Разбор таймаута на телефоне

Пользователь прислал общий таймаут карты; успешный рендеринг не подтверждён.
HEAD к GL JS/CSS v3.33.0 с ноутбука вернул 200 для обоих ресурсов (без токена,
тайлов или маршрутов). Это не доказывает доступность CDN с телефона.

Исправлена обработка: поздний ready после таймаута теперь восстанавливает карту;
последний статус можно повторно получить через onLoadEnd, не теряя событие ready.
CSS подключён неблокирующим способом. Добавлены фиксированные этапы document /
library / style и коды MAP_WEBVIEW/MAP_DOCUMENT/MAP_LIBRARY/MAP_STYLE для таймаута
30 секунд; сырые URL/токены не передаются. Ошибки auth/webgl/load имеют отдельные
коды. Причина конкретного таймаута на телефоне пока не установлена.
VM-тест проверяет этапы и повторную отправку ready; телефон требует повторной проверки.

## Уточнение MAP_STYLE

Пользователь подтвердил код MAP_STYLE: HTML/GL JS и конструктор карты прошли,
но событие load не наступило. Это ещё не различало ожидание стиля и тайлов.
Изменено: style.load открывает карту и маркеры, load отдельно подтверждает
начальную подложку. Ожидание тайлов даёт неблокирующий индикатор/MAP_TILES,
а styledata отмечает переход к ресурсам стиля (MAP_SOURCES при таймауте).
Непрозрачный экран загрузки заменён плавающим блоком, чтобы WebView оставался
видимым во время первого рендера. Зависание GPU/сети на телефоне этим не доказано;
нужна повторная проверка. VM-тест проверяет создание маркеров после style.load
без наступления load, а затем отдельное сообщение готовности подложки.
Новых реальных запросов Mapbox в этом исправлении не выполнялось.

По предоставленному URL подключён опубликованный стиль
`mapbox://styles/mpaprotski911/cmvfoqaqv00fl01s60qij53my` вместо Streets v12.
URL вынесен в MAP_STYLE_URL. Выполнен один GET Styles API с публичным токеном:

Это проверка доступности стиля, не подтверждение исправления загрузки на телефоне.

## MAP_TILES на CMF Phone 2

На скриншоте подтверждены стиль, DOM-маркеры и контролы; подложка не видна.
Причина сетевого/worker/GPU-зависания пока не установлена. Inline WebView
получил стабильный HTTPS baseUrl `https://app.vandrouka.local/` и явный аппаратный
слой Android. Этот виртуальный host не загружается из сети; он задаёт origin
HTML, CORS и blob-workers. Внутренняя навигация допускает только точный baseUrl.
Если публичный токен имеет доменные ограничения, нужно учитывать этот origin.

Для следующей диагностики добавлен безопасный tile-status без URL/токенов:
наблюдался ли render, запуск source и хотя бы один isSourceLoaded. При таймауте
показывается MAP_RENDER / MAP_SOURCE_START / MAP_SOURCE_PENDING / MAP_TILE_PENDING.
Эти признаки помогают сузить проблему, не доказывают загрузку всех источников.
Синтетические события проверены VM-тестом. Исправление на телефоне пока не подтверждено.
Новых платных/токенизированных запросов Mapbox на этом шаге не выполнялось.

этим общим подтверждением не зафиксирована. Коммит/push не выполнялись.
