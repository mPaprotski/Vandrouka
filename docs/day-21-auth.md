# 21 октября — серверная авторизация

Этап выполнен досрочно 20 октября 2026 года. Мобильные формы и refresh/logout относятся к 22 октября.

## Реализация

Миграция `000012_create_auth.sql` добавляет `users` и `sessions`. Email уникален и хранится в нижнем регистре. Регистрация создаёт пользователя и первую сессию одной транзакцией; сбой записи сессии не оставляет пользователя без результата регистрации. Конкурентные регистрации одного адреса не создают дублей.

| Метод | Путь | Результат |
|---|---|---|
| POST | `/v1/auth/register` | 201: пользователь и access-сессия |
| POST | `/v1/auth/login` | 200: пользователь и новая access-сессия |
| GET | `/v1/me` | 200: владелец access-сессии |

POST принимает только JSON `{ "email": "walker@example.com", "password": "example password 123" }`. Другие поля и второй JSON-документ отклоняются, тело ограничено 4096 байтами. Email: ASCII до 254 байт, внешние пробелы убираются, регистр игнорируется. Точки и `+` не преобразуются. Пароль: 12–128 Unicode-символов, не более 512 байт UTF-8; пробелы сохраняются. Отдельных обязательных наборов символов нет.

Ответ входа/регистрации: `user` (id/email/created_at), `access_token`, `token_type=Bearer`, `expires_at`. Access-токен — 32 случайных байта в base64url без padding, срок 24 часа. В БД хранится только SHA-256 токена. `/v1/me` принимает ровно один заголовок `Authorization: Bearer <token>`; query/cookies не используются. Пароль и хэши не возвращаются. Ответы auth имеют `Cache-Control: no-store`; серверные request IDs и общий JSON-конверт ошибок сохранены.

Пароли: Argon2id, 19 MiB, 2 итерации, 1 поток, случайная соль 16 байт и результат 32 байта. Параметры соответствуют [рекомендации OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). Проверка ограничивает параметры сохранённого хэша и сравнивает результат constant-time. Неизвестный email проходит dummy-проверку Argon2id и получает ту же ошибку, что неверный пароль. Непрозрачные случайные токены соответствуют подходу [OWASP к идентификаторам сессий](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

Ошибки: 400 invalid_request, 401 invalid_credentials/unauthorized, 409 email_exists, 413 request_too_large, 415 unsupported_media_type, 429 rate_limited, 503 auth_busy, 500 internal. Повторная регистрация явно сообщает 409; сокрытие существования email не заявляется. Ошибки SQL и внутренние детали в ответ не попадают.

## Ограничения попыток

Register/login делят лимиты одного процесса: 10 запросов за минуту по peer-IP, 5 корректно разобранных запросов за минуту по нормализованному email. Считаются и успешные попытки. Идентификатор email в памяти — SHA-256, не сам адрес. Не более двух одновременных операций с паролями и 4096 записей ограничителя; переполнение не отключает защиту. 429 возвращает Retry-After: 60, занятость — 503 и Retry-After: 1.

X-Forwarded-For и X-Real-IP не доверяются. За reverse proxy все клиенты могут иметь общий peer-IP: перед внешним развёртыванием требуется явно настроить доверенные прокси и внешние лимиты. Лимит по email допускает временный отказ для адреса после чужих попыток; постоянной блокировки аккаунта нет. Redis для одного экземпляра API не добавляется.

## Проверки

- Автономные тесты: соль, правильный/неправильный пароль, повреждённый хэш, валидация, уникальные токены, неизвестная/истёкшая сессия, граница времени, отмена и ошибка хранилища.
- HTTP: register/login/me, JSON-ошибки, no-store, request ID, неизвестные поля, размер тела, неправильный тип содержимого, IP/email/конкурентные лимиты, поддельный forwarded IP.
- PostgreSQL на отдельной тестовой БД: сохранение хэшей, восстановление сессии новым экземпляром сервиса, отзыв/истечение, разные владельцы, параллельные регистрации, rollback при ошибке сессии.
- Миграция up/down/up проверена на тестовой БД; локальная основная БД получает только up без очистки каталога.
- Полный Go-прогон с `-race`, `go vet`, gofmt, OpenAPI и Docker build прошли.
- Обновлённый локальный Docker API проверен двумя временными аккаунтами: регистрация, дубликат, неверный пароль, login, me, отсутствие/неизвестный токен и разделение владельцев. Реальные ответы сверены со схемами OpenAPI. Аккаунты и сессии после проверки удалены. Каталог сохранил 60 мест и пять обогащённых карточек. Вызовов Mapbox не было.

Тесты не используют Mapbox и не требуют Android-эмулятора. CI уже запускает все Go-тесты с PostgreSQL и миграции, поэтому новые тесты входят в существующий job.

## Что дальше

22 октября: refresh с ротацией и отзывом, logout, мобильные login/register, SecureStore и восстановление сессии; правила visits/GPS/уровней. Пока access-сессия не продлевается автоматически, пользователь может войти повторно. Email-подтверждение, OAuth и восстановление пароля в этом этапе отсутствуют. Приватные игровые эндпоинты ещё не добавлены; публичные каталог, карта и маршрутизация продолжают работать без входа. Для внешнего развёртывания auth нужен HTTPS; локальная проверка выполняется по LAN/localhost.

Остаются отдельные проверки на телефоне по дням 19–20 и полевой обход подходов к пяти местам.

Срок новых сессий настраивается переменной `AUTH_ACCESS_TTL` (по умолчанию `24h`, например `72h` для трёх суток). Нулевой/отрицательный срок останавливает запуск. Изменение применяется при выдаче новой сессии; существующий `expires_at` не переписывается.
