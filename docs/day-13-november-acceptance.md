## Проверка полученного APK

Из корня проекта выполнить, подставив путь к файлу и адрес развёрнутого API.

```bash
python3 scripts/check_field_readiness.py --apk /absolute/path/vandrouka.apk --api-origin https://YOUR-API.onrender.com --online
apksigner verify --verbose --print-certs /absolute/path/vandrouka.apk
aapt dump badging /absolute/path/vandrouka.apk
```

Сохранить SHA256 APK из preflight, package, versionName, versionCode и SHA256
сертификата подписи. Ожидаемый package приложения `by.vandrouka.app`.
Для обновления поверх предыдущего APK сверить package и сертификат,
проверить увеличение versionCode. Ключ подписи хранится приватно.

Зафиксировать commit исходников и digest backend. Текущий HEAD `783dd2d`,
рабочее дерево содержит последующие изменения. Одна ссылка на этот commit
не идентифицирует проверенную версию приложения целиком.

Для каждого FAIL записать сборку, шаги, ожидаемый и фактический результат,
request ID при наличии. После исправления повторить исходный сценарий
и затронутые автоматические проверки. Полную переустановку проводить на
тестовых данных, предварительно записав результаты предыдущего прохода.

Для refresh можно войти заранее и повторить проверку после истечения access
token с его штатным сроком 24 часа. Это отдельный пункт ручного отчёта.
