# 22 октября — refresh/logout и вход в Expo

Этап реализуется 20 октября 2026 года после серверных этапов 23–24.
Стек сохранён: Expo Go SDK 57, физический Android, Mapbox GL JS через WebView.
Mapbox-запросы и Android-эмулятор для этой работы не нужны.

## Сервер

Миграция `000015_refresh_sessions.sql` добавляет `session_families` и хэши refresh-токенов
в sessions. Существующие access-сессии без family не удаляются и действуют до своей даты истечения;
для refresh после обновления требуется новый вход. Откат миграции сохраняет access-строки и их revoked_at.

Register/login теперь возвращают access_token, refresh_token, expires_at, refresh_expires_at,
token_type и user. Access по умолчанию **24 часа** (`AUTH_ACCESS_TTL`), refresh-family —
**30 дней** (`AUTH_REFRESH_TTL=720h`). Refresh имеет абсолютный срок, ротация не продлевает его.
Access не может пережить срок family. В БД только SHA-256 обоих токенов, не исходные строки.

| Метод | Endpoint | Результат |
|---|---|---|
| POST | `/v1/auth/refresh` | Новая пара, предыдущий access отозван |
| POST | `/v1/auth/logout` | 204, вся текущая цепочка отозвана |

Оба принимают JSON `{"refresh_token":"<credential>"}`, не URL/cookies. Заголовки auth — no-store,
включая ошибки/таймауты. Попытки refresh/logout вместе ограничены 30 запросами в минуту на peer-IP,
forwarded headers не доверяются. Другие устройства того же аккаунта имеют отдельные family.

Refresh одноразовый. Строка family блокируется на время ротации/отзыва. Повтор уже потреблённого
refresh отзывает всю цепочку, включая новую пару; параллельный повтор не создаёт две активные пары.
Logout работает и при истёкшем access; повторный logout/неизвестный корректно сформированный refresh
возвращает 204, чтобы не раскрывать существование сессии.

Клиент сериализует refresh. Если сервер уже выполнил ротацию, но ответ потерян в сети,
старый токен восстановить нельзя: повтор приведёт к отзыву и запросу нового входа.
Сырые токены или ответы ротации не кешируются в открытом виде ради обхода этой защиты.

## Мобильное приложение

Маршрут `/auth` содержит вход/регистрацию и подтверждение пароля. Email и пароль проверяются
до отправки; пароль не обрезается и не сохраняется на диске. Ошибки API, Request ID,
занятость, неправильный пароль и отсутствие сети отображаются в форме.

В «Профиле» доступны вход, email текущего пользователя и выход. «Посещения» требуют
проверенной сессии и пока честно сообщают, что история ещё не подключена.
Карта/каталог доступны без аккаунта; при входе/выходе WebView не пересоздаётся специально.

`expo-secure-store` установлен через expo install для SDK 57, добавлен config plugin.
Токены сохраняются одним record в SecureStore, без AsyncStorage/localStorage, без биометрического
requireAuthentication, который не нужен для этого сценария Expo Go. Android backup настраивается
плагином. Документация: [SecureStore SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/securestore/),
[Expo Router auth](https://docs.expo.dev/router/advanced/authentication/).

Record привязан к нормализованному API origin: при изменении адреса backend он сбрасывается,
токены не отправляются другому серверу. Это может потребовать нового входа после смены LAN-адреса.
Данные пользователя не публикуются как authenticated до проверки `/v1/me`; при истечении access
выполняется refresh. При возврате приложения в foreground сессия проверяется заново.
При ошибке сети во время восстановления приватные экраны заблокированы, credentials сохранены для retry.

Refresh имеет single-flight, сохранения SecureStore последовательны. Logout/смена аккаунта
увеличивают поколение сессии: старые ответы не попадают в новый профиль, старый refresh не восстанавливает
вышедшего пользователя. Новая пара сохраняется до публикации состояния authenticated.
Ошибка SecureStore не превращается в успешный вход; выданная сессия отзывается best effort.

### Выход без сети

Сначала записывается marker отзыва без активной сессии, затем закрывается локальный доступ.
При недоступном backend UI сообщает, что выход выполнен на устройстве, а отзыв завершится после подключения.
При перезапуске marker не восстанавливает старый аккаунт: отправляется logout, затем marker очищается.
До нового входа очередь отзыва должна быть обработана. Если само SecureStore не удалось обновить,
приложение сообщает об ошибке и предлагает повторить действие; оно не обещает завершённый выход.
Удалённый отзыв без сети физически невозможен и не имитируется локальным флагом.

## Зафиксированные игровые правила

По решению пользователя: радиус 50 м, accuracy до 30 м, фиксация не старше 120 секунд
и не более 30 секунд в будущем. Уровни: 0/100/300/600/1000/1500/2100/2800/3600/4500 XP.
Подробная спецификация и границы: [правила MVP](game-rules.md). Реализация GPS/XP API остаётся днём 25,
серверного профиля прогресса — днём 29.

## Проверка

Автономные мобильные тесты: auth transport/декодирование, восстановление, истечение, одиночный refresh
при конкуренции, offline logout + restart, смена аккаунта, запоздалые ответы и ошибки storage.
PostgreSQL: хэши, ротация/абсолютный срок, replay, параллельный refresh, отзыв всей цепочки,
независимость другого устройства, ограничения/валидация HTTP. Миграция up/down/up — на отдельной тестовой БД.

Прошли полный Go `-race` с отдельной PostgreSQL-БД, vet/build, мобильные тесты/typecheck/lint,
OpenAPI, Android export без эмулятора и Docker build. Миграция применена локально только через up,
с сохранением каталога. Обновлённый backend запущен.

Мобильный API-клиент и тот же native-free контроллер сессий проверены против настоящего локального API:
регистрация, 24h/30d, восстановление из сохранённого record, реальный 401 → refresh, replay с отзывом,
независимое устройство, logout и offline marker → restart → reconnect. Native SecureStore в этой
сквозной проверке заменён памятью; его работа на устройстве ещё не проверена. Временный аккаунт удалён,
каталог сохранил 60 мест, Mapbox не вызывался.

В проверке обнаружено и исправлено расхождение точности timestamp между Go и PostgreSQL:
время выдачи нормализуется к микросекундам, поэтому абсолютная дата refresh совпадает до/после ротации.
Тесты не заменяют проверку настоящего SecureStore на телефоне.

На физическом телефоне ещё нужно:

1. Перезагрузить Expo Go, открыть «Профиль», зарегистрироваться и увидеть свой email.
2. Закрыть и открыть приложение — профиль должен восстановиться после проверки сервера.
3. Выйти, затем войти другим аккаунтом — старый email и приватное состояние не показываются.
4. Отключить доступ к backend, выполнить выход, перезапустить приложение — старый аккаунт не возвращается.
5. Восстановить сеть, повторить подключение, войти; проверить неправильный пароль и повторную регистрацию.

Без физического устройства эти пункты остаются непроверенными, хотя SecureStore входит в Expo Go.
