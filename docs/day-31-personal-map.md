# 31 октября — личная карта

В «Исследовать» карта и список используют общие отметки посещений:
- ✓ зелёный маркер — место посещено;
- ○ коричневый маркер — ещё не посещено;
- ● нейтральный маркер — статус неизвестен или пользователь не вошёл.

После входа доступны фильтры «Все», «Мои места», «Новые». Выбор личного фильтра
отключает стартовую подборку и показывает весь каталог Минска; подборку можно
включить снова. Счётчик считает уникальные посещённые места текущего каталога,
а не визиты, фотографии или XP. Неактивные места остаются в Visits,
но не добавляются на карту активного каталога.

## Источник данных и обновление

Используется существующий приватный History API: загружаются все страницы,
PlaceID объединяются в множество. Публикуется только полный результат.
Повторные посещения не увеличивают число открытых мест. Скрытые посещения
не участвуют, как и в Visits; удаление фотографии не убирает отметку.
Накопленный XP в Profile остаётся независимым от скрытия истории.

При фокусе вкладки, возвращении из фона или ручном обновлении история
перечитывается. После подтверждения посещения возвращение на карту обновляет
отметку без перезапуска. Visits и Profile также читают серверные данные при фокусе.
При ошибке страницы частичные отметки не выдаются за полный прогресс:
личные фильтры скрыты, каталог доступен со статусом «неизвестно» и повтором.
Новые записи между страницами подчиняются keyset-контракту дня 30;
ручное обновление получает новый верх истории.

Каждый экран привязан к владельцу сессии, каждый запрос проверяет владельца.
При смене аккаунта экран и WebView размонтируются. При уходе с вкладки или
в фон запрос отменяется и личные отметки очищаются; поздние ответы игнорируются.
В WebView передаются только поля публичного места и boolean visited, без
истории, фотографий, GPS посещения или Bearer. HTML/стиль карты при обновлении
отметок не пересоздаётся: изменяются маркеры через существующий bridge.

## Проверка

Автотесты: все страницы, повторные PlaceID, пустая история, неизвестное состояние,
ошибка второй страницы, отмена, циклический курсор, новая загрузка после
подтверждения/смены аккаунта. Маркеры и сброс личной отметки проверяются
в VM с заглушкой Mapbox, без сети. Сквозной локальный сценарий дополнен
проверкой множества посещённых мест до и после подтверждений.

На телефоне ещё требуется: войти → открыть карту и список → переключить
«Мои места»/«Новые» → подтвердить посещение → вернуться на карту → проверить
Visits и Profile → перезапустить Expo Go → сменить аккаунт.
Ранее открытые полевые проверки дней 28–30 этим не закрываются.
Mapbox API и Android-эмулятор во время разработки не используются.

Текущее ограничение: клиент читает полную историю для построения отметок.
Для большой истории стоит добавить компактный серверный список уникальных
PlaceID; до этого оптимизация не меняет корректность и не ограничивает число страниц.

Результаты: прошли 14 тестовых файлов mobile, typecheck, lint,
`git diff --check` и Android/Hermes export (`/tmp/vandrouka-day31-export`).
Локальные контейнеры были остановлены; после запуска PostgreSQL/MinIO/API
сквозной сценарий прошёл с двумя временными аккаунтами и очисткой данных.
Проверены пустая личная карта, уникальный PlaceID после повторных подтверждений,
восстановление сессии и история, приватное фото и сохранение XP.
Экспорт не заменяет проверку WebView, навигации и GPS на физическом телефоне.
