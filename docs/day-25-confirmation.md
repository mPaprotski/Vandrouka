# День 25 — подтверждение посещения и XP

Реализовано досрочно 20 октября 2026 года. Backend подтверждает готовое фото
и GPS, сохраняет посещение и первую награду атомарно. Мобильная камера/upload добавлены [днём 26](day-26-mobile-camera.md); отправка посещения из интерфейса добавлена [днём 27](day-27-mobile-confirmation.md).

## Запрос и ответы

`POST /v1/places/{id}/visits`, Bearer access token, ровно один `Idempotency-Key: UUID`.
`Content-Type: application/json`, до 4096 байт; неизвестные поля отвергаются.

```json
{
  "photo_id": "00000000-0000-4000-8000-000000000001",
  "location": {
    "lat": 53.9032997,
    "lon": 27.5561469,
    "accuracy_m": 10,
    "observed_at": "2026-10-25T09:00:55+03:00"
  }
}
```

`201` — новое подтверждение, `200` — повтор подтверждённого исхода;
оба содержат `visit` и исходный `xp_awarded` (100 или 0).
`422` — сохранённый отказ: `visit`, `xp_awarded: 0`, `error: {code, message}`.
Повтор отказа также возвращает 422 и исходное посещение.
`400` — неверные параметры/ключ, `401` — нет сессии, `404` — нет места или своего
неудалённого фото для этого места, `409 idempotency_conflict` — изменённое тело/место
с прежним ключом, `409 photo_already_used` — фото уже подтверждает посещение.
`413` — размер запроса, `415` — Content-Type; ошибки БД возвращаются без внутренних подробностей.

Все ответы `Cache-Control: no-store`. В публичном JSON нет user ID, object_key,
координат, distance/accuracy, fingerprint или idempotency key. Логи содержат только
шаблон endpoint, Request ID и служебные показатели, без тела и GPS.

## Правила и транзакция

Сервер фиксирует `received_at` до аутентификации/чтения тела. Расстояние — Haversine
с радиусом Земли 6371008.8 м. Точные включительные границы: расстояние ≤ 50 м,
accuracy от 0 до 30 м, observed_at от received_at − 120 с до received_at + 30 с.
Сравнения не округляются; микросекундная точность PostgreSQL применяется только
при хранении, после проверки. Неизвестная/null accuracy не считается нулём.
Timestamp с offset нормализуется к UTC; NaN/Infinity/неверные координаты отвергаются.

Пороги задаёт сервер через `VISIT_RADIUS_M=50`, `VISIT_ACCURACY_M=30`,
`VISIT_MAX_AGE=120s`, `VISIT_FUTURE_SKEW=30s`. Compose пробрасывает их в API.
Некорректная конфигурация останавливает запуск. Запрос не может изменять пороги.

1. Заблокировать пользователя `FOR UPDATE`: параллельные подтверждения одного
   владельца сериализуются, разные владельцы работают независимо.
2. Проверить сохранённый user/key. SHA-256 строится по place ID и нормализованным
   photo UUID, числам и UTC timestamp (включая наносекунды). Регистр UUID и offset
   одного момента не меняют тело. Повтор возвращает исходный visit/XP до проверки
   текущего GPS, фото, активности места или скрытия истории. Изменённое тело — 409.
3. Заблокировать место `FOR SHARE`, своё фото `FOR UPDATE`; отсутствующее,
   чужое, удалённое фото или фото другого места — 404. Уже подтверждённое — 409.
   Фото должно быть `ready`; полноту проверенных метаданных гарантирует схема БД.
4. Выбрать первый отказ в порядке: inactive_place → photo_not_ready → poor_accuracy
   → stale_location → future_location → too_far. Записать rejected или confirmed.
5. Только для confirmed вставить +100 XP с `ON CONFLICT(user_id,place_id) DO NOTHING`:
   первое посещение даёт 100, новое посещение уже награждённого места — 0.
6. Коммит посещения и награды вместе. Любая ошибка откатывает оба изменения.

Отказ не расходует фото: после исправления нужен новый ключ и свежая фиксация.
Новое подтверждённое посещение требует нового фото. Скрытие истории/удаление фото
сохраняет XP и защиту от повторной первой награды. Сам endpoint скрытия истории —
следующий этап. GPS и наличие фото не доказывают подлинность снимка; распознавание
содержимого и защита от поддельного GPS в MVP не входят.

## Проверено

- Unit-тесты: точные границы расстояния/accuracy/возраста/будущего, превышения на
  долю метра/наносекунду, порядок отказов, Haversine с фиксированными ожиданиями,
  нормализация UUID/UTC и неверные данные.
- HTTP: авторизация, обязательные/null поля, приватность, лимит тела, Content-Type,
  неизвестные поля, лишний JSON, коды ошибок и replay.
- Локальная тестовая PostgreSQL: первое/повторное место, сохранённый отказ и
  исправление с тем же фото, чужие/удалённые/отсутствующие фото, неготовое фото,
  неактивное место, GPS-отказы, конкурентные повторы/конфликтующие тела,
  параллельная первая награда, сохранение XP после скрытия истории/удаления фото.
- Принудительная ошибка INSERT XP после INSERT visit: посещение откатывается.
- Полные Go-тесты с `-race` и тестовой PostgreSQL, `go vet`, build, gofmt и diff check.
- OpenAPI: примеры, границы запросов и соответствие 18 реализованным endpoint.
- Реальный локальный API + PostgreSQL + приватный MinIO: загрузка PNG,
  confirm +100, новый visit +0, replay, 409, too_far/422 и исправление, чужое фото/404.
  В БД осталась ровно одна награда 100 XP; временные аккаунты и фото удалены.
  API пересобран и запущен локально; каталог содержит прежние 60 мест.

Mapbox не вызывался, Android-эмулятор не запускался. Проверка с реальными GPS и
камерой в Expo Go на физическом телефоне остаётся на днях 26–28. Расчёт уровней и
