## Пункт 3: свежая проверка исходного порядка — выполнен

Service.PrepareBaseline получает параметры, исходный порядок и ID операции.
Один раз загружается полный активный каталог города: отсутствие базового ID или
цели операции даёт ErrPlaceNotFound (для будущего 404) до оплачиваемых вызовов.
Место вне выбранных категорий не считается отсутствующим: для базового маршрута
это ErrConstraintsViolation. Неизвестный город сохраняет ErrCityNotFound.

Matrix строится один раз для свежего каталога; Directions вызывается для точного
исходного порядка от старта без возвращения. EvaluateOrder пересчитывает бюджет,
расписания, посещения, стоимость и метрики по подтверждённым legs, с тем же Planner
и настроенными весами. Geometry=false не отключает Directions. Приближённый
бюджет Matrix не используется для отказа до окончательных данных Directions.

Baseline сохраняет Prepared, исходную Matrix, собственную копию порядка и
VerifiedVariant. Следующие шаги должны использовать этот снимок для результата
и diff, без повторной загрузки каталога. Подтверждённые legs не меняют исходную
Matrix. Не принимаются сохранённые клиентские totals или geometry.

Невыполнимость, недостижимые legs и NoRoute — ErrConstraintsViolation для 422.
Ошибка провайдера/квоты, повреждённые legs или geometry — ErrRoutingUnavailable
для 503. Отмена контекста сохраняется. HTTP-преобразование этих ошибок ещё не
подключено; add/remove остаются следующими пунктами.

Тесты без БД/сети проверяют независимо рассчитанные 1922.3579 секунды, .6 км,
250 копеек, timezone, исходный/обратный порядок, ровно 35 минут и превышение
на микросекунду, свежие цены/закрытие, недостижимость, NoRoute, квоту, неверные
legs, ID до routing, категории, отмену и обязательную проверку без геометрии.

## Пункт 4: удаление и заполнение — выполнен

Service.Remove получает проверенный Baseline и удаляемый ID. Каталог и Matrix
не загружаются повторно. Оставшиеся остановки сохраняют взаимный порядок;
переходы после удаления заново проверяются Directions, включая новый переход
между бывшими соседями удалённого места. Удаляемый ID исключён из всех вставок
и последующих вызовов Directions.

Свободное время заполняется жадными вставками подходящих категорий. Для каждого
кандидата проверяются позиции вставки через EvaluateOrder; лучшая допустимая
позиция ранжируется по Score, затем длительности. Равенства разрешаются стабильным
порядком каталога и позиций, результат воспроизводим. Это ограниченный жадный
поиск, а не гарантия глобально лучшего или максимально заполненного маршрута.

После каждой выбранной вставки проверяется весь порядок через Directions.
Невыполнимая вставка/NoRoute пропускается, при отсутствии допустимых вставок
возвращается последний подтверждённый маршрут. Ошибка провайдера или отмена
завершает операцию ошибкой, не маскируется успешным частичным результатом.
Вставки не удаляют другие исходные остановки. Если сам порядок оставшихся
остановок стал невыполнимым из-за новых переходов, возвращается
ErrConstraintsViolation; скрытого увеличения бюджета нет.

Удаление единственной остановки допускает пустой маршрут (нулевые метрики,
geometry=nil, без Directions-вызова для пустого порядка); заполнение может
добавить другие места. Отключённая геометрия сохраняет обязательную проверку
непустых порядков. Baseline и исходная Matrix не изменяются.

Тесты: удаление первой/средней/последней остановки, запрет повторного появления,
заполнение, сохранение взаимного порядка, пустой результат, заполнение из пустого,
точные 1980 секунд/.3 км/0 копеек, нулевой бюджет билетов, закрытые места,
категории, превышение после Directions, NoRoute, квота, отмена и seed-повторяемость.
Проверены тесты routes/http/planner с -race, go vet и форматирование.
HTTP и окончательный diff остаются последующими пунктами.
Коммит: Recalculate routes after removing a place.

## Пункт 5: обязательное добавление — выполнен

Service.Add использует тот же Baseline, активный каталог и Matrix. ID должен
отсутствовать в исходном порядке и подходить выбранным категориям. Отсутствующий
ID — ErrPlaceNotFound, несовместимые категории — ErrConstraintsViolation.

Вначале проверяются все позиции вставки с сохранением исходных остановок.
EvaluateOrder по Matrix ранжирует позиции (Score, длительность, стабильный
порядок), Directions проверяет реальную выполнимость. Matrix не отбрасывает
позиции окончательно: его завышенная длительность не блокирует допустимый
результат Directions. При NoRoute/нарушении ограничений пробуется следующая
позиция; ошибки провайдера и отмена немедленно возвращаются вызывающему коду.

Если вставка невозможна, последовательно исключаются исходные остановки:
обычные до must-see, меньшая importance первой, равенство — исходный порядок.
После каждого исключения позиции проверяются заново. Это воспроизводимый жадный
поиск замен, без перебора всех подмножеств и гарантии оптимального сохранения.
Последняя попытка — добавляемое место отдельно. Во всех попытках оно обязательно;
успех без него невозможен. Бюджеты не расширяются. Если выбранный поиск не находит
допустимого варианта — ErrConstraintsViolation для будущего 422.

Сумма осмотров и известных цен — строгие нижние границы: если они уже превышают
лимиты, бессмысленные Directions-вызовы пропускаются. Неизвестная цена учитывается
по прежним правилам как неподтверждённая, не объявляется бесплатной. Число позиций
ограничено размером исходного маршрута, контекст проверяется в циклах; каждая
Directions-проверка может использовать квоту, автоматических повторов нет.
Заполнение дополнительными новыми местами после add на этом пункте не выполняется.

Тесты подтверждают вставку без замен, замену нескольких остановок, приоритет
сохранения must-see, точный бюджет/превышение на микросекунду, целевые расходы,
нулевой лимит, неизвестную цену, закрытие, NoRoute, переход к другой позиции,
завышенную Matrix, квоту, отмену, обязательный ID, геометрию и повторяемость.
Тесты routes/http/planner с -race, go vet и форматирование пройдены.
HTTP-обработчик и diff остаются последующими пунктами. Реальный Mapbox не вызывался.

## Пункт 6: итоговый ответ и diff — выполнен

BuildRecalculateRouteResponse принимает проверенный Baseline и итоговый
VerifiedVariant. Оба маршрута сериализуются и проверяются по одному Prepared:
свежие карточки, timestamps, подтверждённые переходы, стоимости и метрики.
Порядок Baseline.Order обязан совпадать с исходными остановками. Повреждённые
метрики, seed, пустой маршрут с геометрией или ненулевыми суммами отклоняются.

Переиспользуется сериализация generate; внутренний режим разрешает пустой
variant только для recalculate. Пустой результат имеет нулевые метрики, [] для
stops/labels, {} для category_counts, BYN, cost_complete=true и geometry=null.
Generate по-прежнему отклоняет пустые варианты.

DiffRoutes задаёт ID добавленных/удалённых остановок в соответствующем порядке;
ExplainDiff использует имена из свежих карточек. Числовые delta вычисляются
как итоговые точные секунды/метры/копейки нового маршрута минус исходного,
без округления через минуты/километры. PricesConfirmed=true только если цены
обоих маршрутов полные; неизвестные цены явно отмечаются в тексте. Перестановка
не создаёт added/removed ID. Ответ не меняет исходный снимок.

Тесты: удаление, пустой результат (-1922.3579 секунд/-600 метров/-150 копеек),
добавление (+361.3456 секунд/+300 метров/+275 копеек), перестановка,
известные/неизвестные цены, точность, JSON-коллекции и повреждённые результаты.
Сериализованный Go-ответ recalculate проверяется по OpenAPI новым аргументом
check_openapi.py --recalculate-response; проверка добавлена в CI.
Эндпоинт по-прежнему planned, его регистрация — пункт 7.

## Пункт 7: HTTP-эндпоинт — выполнен

RegisterRecalculation подключён в cmd/api с общим сервисом и Mapbox-клиентом.
POST /v1/routes/recalculate выполняет строгую валидацию, PrepareBaseline,
Add/Remove и BuildRecalculateRouteResponse. Один контекст на 180 секунд охватывает
обе фазы, общий лимит тела — 64 КиБ. JSON кодируется до статуса 200.

Ответы: 200 (включая пустой variant), 400 invalid_request, 404 not_found,
422 constraints_violation, 503 routing_unavailable (также отмена/таймаут),
500 internal. В ответ не попадают сообщения провайдера или токен.
OpenAPI помечает recalculate implemented; проверка регистрации учитывает
новый файл обработчика. Проверка фактического HTTP-ответа добавлена в CI.

HTTP-тесты с настоящим routes.Service и фиксированными routing-данными без сети
проверяют add, remove/refill, пустой результат, невыполнимое добавление,
закрытый исходный маршрут, неизвестный ID, неверную операцию и ошибку квоты.
Тесты с -race, vet, форматирование и OpenAPI пройдены. Полная регрессия и
