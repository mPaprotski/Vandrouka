# Этап 19 октября — карточка и положение пользователя

## Реализовано

- Карточка запрашивает полный PlaceDetails: описание, категории, время осмотра,
  расписание, исключения, цены, известность данных и ссылки. JSON проверяется.
- Расписание выводится Пн–Вс с отдельными интервалами для перерывов; ночной
  переход обозначен. Особые даты показываются отдельно. Время — местное по
  часовому поясу города из /v1/cities. Статус «открыто сейчас» не вычисляется.
- Неизвестная цена не превращается в бесплатный вход. Известный ноль показывается
  как бесплатно. Дата проверки и первичные источники доступны в карточке.
- «Как добраться»: системный geo intent на Android, Apple Maps на iOS,
  резервная пешеходная ссылка Google Maps в браузере. Начальная точка не передаётся;
  её определяет внешнее приложение. Для этих ссылок API-ключи не нужны.
  Открытие ссылки — по нажатию, URL источников ограничены HTTP(S) без credentials.
- В текущем API нет полей фотографий/лицензий; в каталоге только ссылки на
  страницы-источники. Карточка показывает заглушку, не извлекает изображения
  со сторонних страниц и не выдаёт ссылку на статью за фотографию.
  Реальные фото с разрешённым источником относятся к подготовке контента 20 октября.
- Установлен expo-location через expo install (SDK 57 / Expo Go).
  Кнопка «Моё местоположение» запрашивает только foreground permission.
- Получается одна свежая координата (не старше 30 секунд), с таймаутом 20 секунд.
  Используется кратковременный watchPositionAsync; подписка удаляется при первой
  координате, отмене, таймауте, уходе с экрана и переходе приложения в фон.
  Поздняя регистрация после отмены также удаляется. Автоматического трекинга нет.
- Точка передаётся в локальный WebView, отображается синим маркером, камера
  центрируется на ней. Точность показывается отдельно; null не заменяется нулём.
  Положение обозначено как снимок на момент запроса, а не live tracking.
- При отказе/постоянном запрете/GPS off/таймауте каталог и карта доступны.
  Для постоянного запрета есть переход к настройкам. При фоне/уходе точка очищается,
  новый запрос запускается только кнопкой. WebView сам GPS не запрашивает.
- Координаты не сохраняются и не отправляются в backend; Mapbox может загружать
  тайлы при перемещении камеры. Фоновые разрешения/сервисы не включены.

## Проверки

Без сети: декодирование карточки, интервалы и переход даты, неизвестная/нулевая
цена, кодирование внешней навигации и опасные URL, свежесть/точность координат,
отказ/блокировка/GPS off, отмена, таймаут, поздняя регистрация и очистка watcher,
маркер положения в фиктивном Mapbox/DOM. Настоящий GPS не использовался.

Локальный backend: API-клиент успешно получил health, один город, 60 мест и
карточку художественного музея (6 интервалов, одна цена, три источника).
Это проверка клиента из Node, а не подтверждение новых экранов на телефоне.

## Проверить пользователю в Expo Go

1. Reload; открыть музей с карты/списка, сверить описание, категории, время,
   расписание, билет и переходы к источникам. Проверить место с неизвестными данными.
2. Нажать «Как добраться», проверить координаты во внешних картах; вернуться назад.
3. На карте нажать «Моё местоположение», разрешить доступ: синяя точка и точность.
4. Повторить с отказом и GPS off: список и карта должны оставаться доступны.
5. Во время определения перейти в профиль/свернуть приложение; вернуться:
   запрос не продолжается, новая точка появляется только после нового нажатия.
6. Проверить постоянный запрет и «Открыть настройки», разрешить и запросить снова.

Сквозные сценарии этого этапа на телефоне ещё не подтверждены. Эмулятор,
реальные Mapbox API в автоматических проверках и нативная сборка не запускались.
Коммит/push не выполнялись.

Итог автоматических проверок: тесты, TypeScript, ESLint, git diff --check,
Expo Doctor (21/21) и офлайн-экспорт Android (1271 модуль) прошли.
Отдельный тест проверяет ровно одну очистку подписки при немедленной первой
координате, включая гонку callback с возвратом native subscription.
