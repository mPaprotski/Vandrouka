# 30 октября — история посещений

Реализованы приватный `GET /v1/users/me/visits` и вкладка «Посещения» в Expo Go.
Требуется действующая сессия; владелец определяется сервером по Bearer-токену.

## Контракт

- Только подтверждённые посещения с `deleted_at IS NULL`, включая повторные визиты.
- Сортировка `created_at DESC, id DESC`; `limit` по умолчанию 20, диапазон 1–50.
- `next_cursor` — непрозрачный курсор следующей страницы либо `null`.
  Следующий запрос передаёт `cursor`; неизвестные и повторные параметры дают 400.
- Курсор сохраняет полную точность времени и ID. Новые записи в начале истории
  не сдвигают следующие страницы. Это keyset-пагинация, а не снимок всей истории:
  записи, добавленные позднее с более ранним временем, могут попасть ниже курсора;
  новые верхние записи появляются после обновления.
- Ответ содержит название, доступность места, часовой пояс города, время,
  ID доступного фото и XP именно этого посещения (100 или 0).
- Удалённое фото возвращается как `photo_id: null`; визит и накопленный XP остаются.
  Неактивное место сохраняется в истории, переход в каталог отключён.
- GPS, идентификатор пользователя, object key, URL хранилища и токены в ответ не входят.
  Ответы приватного API имеют `Cache-Control: no-store`.

## Приложение

При фокусе экрана история перечитывается с сервера; есть пустое состояние,
повтор загрузки и кнопка следующей страницы. Ошибка страницы сохраняет уже
загруженные записи. Поздние ответы после ухода с экрана игнорируются.
История очищается при уходе в фон, смене аккаунта и уходе с экрана.

Открывается только одно фото одновременно: загрузка авторизованным запросом,
проверка JPEG/PNG и размера до 10 MiB, преобразование в data URI в памяти.
Bearer не передаётся в URL изображения; файлового кеша истории приложение не создаёт.
Фото другого пользователя сервер не отдаёт. При выходе из аккаунта приватный
экран размонтируется. После перезапуска данные загружаются заново.

## Проверка

Автотесты покрывают курсоры, стабильный порядок при совпадающем времени,
добавление нового первого визита между страницами, фильтрацию чужих,
отклонённых и скрытых записей, удалённое фото и сохранение XP.
Клиентские тесты проверяют отмену, поздние ответы, повтор страницы,
ошибку следующей страницы, проверку ответа и приватную загрузку фото.
Локальный сценарий `scripts/verify_game_loop.mjs` дополнен проверками истории
после восстановления сессии, пагинации, доступа двух аккаунтов и чтения фото.

Физический телефон: ещё требуется проверить в Expo Go несколько посещений,
открытие/закрытие фото, перезапуск и смену аккаунта. Нативные Camera/GPS/
SecureStore/FileReader не заменяются полным полевым тестом. Старый полевой
чекпоинт дня 28 также остаётся открытым. Mapbox в проверках не используется.

Результат локальной проверки: `go test -race ./...`, интеграционные тесты
history/progress/visits с PostgreSQL, `go vet ./...`, gofmt и `git diff --check`
прошли. Mobile: 13 тестовых файлов, typecheck, lint и Android/Hermes export
прошли. OpenAPI: 20 реализованных endpoint, 29 примеров. Сквозной сценарий
с реальными локальными API/PostgreSQL/MinIO прошёл; временные аккаунты удалены.
Android export не является установочным APK или проверкой нативного UI.
