# Этап 26 октября — OpenAPI

Контракт подготовлен 13 октября 2026. [OpenAPI 3.0.3](openapi.yaml), версия API
0.2.0, описывает пять реализованных GET и два запланированных POST.
`x-implementation-status` различает `implemented` и `planned`.
POST ещё не зарегистрированы в Go-сервере: их реализация — этапы 27–28 октября.

## Генерация

Обязательны `start`, `start_at` и `budget_minutes`. `start_at` — RFC3339
с offset; сервер переводит дату в timezone города. Значения по умолчанию:
город minsk, pace normal, seed 42, все категории, выдача геометрии включена.
Бюджет ограничен 1–1440 минутами; seed — безопасным целым JavaScript
0–9007199254740991. Это ограничения будущего HTTP-контракта, а не изменение CLI.
Неизвестные поля запросов отклоняются, секреты Mapbox в запрос не включаются.

`ticket_budget_minor` — целые копейки BYN: отсутствие/null снимает лимит,
0 задаёт нулевой лимит. Сумма ограничивает известные билеты; неизвестные цены
остаются неизвестными. `cost_complete=false` сообщает, что полной суммы нет.
`hours_unconfirmed` не означает «место открыто». Seed воспроизводит выбор только
при одинаковых каталоге, матрице и настройках, не между обновлениями Mapbox.

После Matrix алгоритм выбирает и оптимизирует варианты; окончательные
последовательности проверяются по Directions. Невыполнимые варианты отбрасываются.
Метки присваиваются после окончательного пересчёта. `include_geometry=false`
убирает геометрию из ответа, но не выключает проверку Directions.

Ответ 200 содержит `seed`, `timezone`, `variants`. Пустой список — корректный
результат, если подходящих маршрутов нет. Вариантов не больше трёх.
Остановки не повторяются; маршрут заканчивается у последнего места.
`variant_id` действует только в данном ответе и не означает сохранение в БД.

## Структуры и единицы

| Структура | Основное содержание |
| --- | --- |
| `RouteVariant` | ID в ответе, профиль, метки, остановки, totals, explanation, geometry |
| `RouteStop` | PlaceID, имя, координаты, arrival/departure, осмотр, предыдущий переход, неизвестные часы/цена |
| `RouteTotals` | Ходьба, осмотр, полное время, расстояние, известная стоимость, полнота цены, количество остановок |
| `RouteExplanation` | Текст, числа неизвестных часов/цен, распределение категорий |
| `RouteDiff` | Знаковые изменения времени/расстояния/цены, добавленные и удалённые ID, подтверждение цен, текст |

Входной бюджет — минуты; точные времена в ответе — секунды, расстояния —
метры, деньги — целые копейки BYN. Время и расстояние могут быть дробными;
не округляются вниз до проверки бюджета. Текст explanation может округлять
для чтения. Пересекающиеся категории не складываются в число остановок.
Геометрия — упорядоченные сегменты polyline6 из текущего Mapbox-адаптера;
при выключенной выдаче или пустом маршруте возвращается null.

## Пересчёт

Клиент передаёт исходный запрос, упорядоченные `base_place_ids` и одну операцию.
Сервер получает актуальные места и переходы заново; клиентские totals не принимает.
Сначала проверяется выполнимость исходного порядка на свежих данных.

- `remove`: ID обязан присутствовать; он исключается из кандидатов для нового
  маршрута. Освободившийся бюджет может заполняться другими остановками.
- `add`: ID обязан отсутствовать; место обязательно включается. Если это
  несовместимо с ограничениями, ответ 422 без скрытого увеличения бюджета.
- Неизвестный/неактивный ID — 404, некорректная операция — 400.
- Если исходный порядок уже невыполним на свежих данных — 422; клиент может
  заново вызвать generate. Исторические totals не используются для diff.

Ответ содержит один `variant` и `diff`, а не новую коллекцию вариантов.
Diff вычисляется как «после минус до» на одной свежей матрице и данных.
Только перестановка не добавляет/удаляет ID. Сравнение полной стоимости
подтверждено лишь при известных ценах обоих маршрутов. `pin` отложен.

## Ошибки и примеры

Единый формат: `{"error":{"code":"...","message":"..."}}`, необязательные
`details`. Описаны 400, 404, 422, 500 и 503. Ошибки Mapbox, токена,
квоты и сетевого срока переводятся в `routing_unavailable` (503), без токена
и внутренних URL в ответе. Локальный запасной провайдер не подразумевается.

Спецификация включает нормальные запросы/ответы, пустую генерацию и удаление
последней остановки. ID и маршрут в примерах условные и не обещают результат
для текущей БД. Проверка охватывает 10 примеров, null/0/отсутствие бюджета,
отрицательный бюджет, повтор категории, неверный pace, время без offset,
лишний access_token и неподдерживаемый pin.

## Зависимости этапов 27–28

Текущий сервер использует общий Timeout 10 секунд и WriteTimeout 10 секунд.
Полная Matrix для каталога 60 мест требует пакетирования и pacing:
10 секунд недостаточно. При добавлении POST нужно выделить маршрутным
обработчикам отдельный срок порядка 180 секунд и согласовать WriteTimeout,
не оставлять их внутри общего десятисекундного middleware.
Mapbox-клиент должен разделяться обработчиками для общего ограничения частоты.
Нужны HTTP DTO с указанными единицами, проверка входа, связывание repository,
Matrix/Planner/Directions и пересчёт с обязательным добавлением/исключением.
На этом этапе эти обработчики не добавлены.

## Валидация и CI

```bash
python3 -m venv /tmp/vandrouka-openapi-env
/tmp/vandrouka-openapi-env/bin/pip install -r scripts/requirements-openapi.txt
/tmp/vandrouka-openapi-env/bin/python scripts/check_openapi.py
```

Проверяются структура OpenAPI, ссылки, примеры и границы запросов.
Реализованные операции автоматически сопоставляются с регистрацией Go-маршрутов.
После установки зависимостей проверка не вызывает БД, Mapbox или другие API.
В CI добавлен тот же шаг. Сами описанные ограничения маршрутов будут проверяться
через HTTP после реализации POST. Обратная связь 3–5 людей по этапу 25 октября
остаётся отдельной незавершённой проверкой качества прогулок.
