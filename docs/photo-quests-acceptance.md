# Приёмка фотоквестов

Для автоматического теста нужен отдельный PostgreSQL. Подставляйте адрес только локальной тестовой базы. Тест создаёт и удаляет свои записи.

```sh
cd backend
POSTGRES_DSN="$QUEST_TEST_DSN" go run ./cmd/migrate up
TEST_DATABASE_DSN="$QUEST_TEST_DSN" go test -p 1 ./...
```

Сквозной тест `TestQuestLifecyclePostgres` использует реальную базу и маршруты HTTP. Вместо Deface и облачного бакета он использует управляемый обработчик и хранилище в памяти. Это позволяет проверить доступ, параллельные запросы, сбои обработчика, сроки удаления и повторы без подключения внешних сервисов. Качество размытия реальных снимков проверяется отдельно.

```sh
cd mobile
npm run typecheck
npm run lint
npm test
```

## Локальная проверка с Deface

Текущий API проверен с PostgreSQL 16, Deface и локальным S3 через Moto. Контейнер API был ограничен 0,1 CPU и 512 МБ. Два тестовых PNG отправлялись одновременно из разных аккаунтов. В исходном прогоне конкурирующий запрос получил `429` примерно через 18 секунд, а активная обработка завершилась по тайм-ауту. После переноса общего ограничения перед декодированием запрос о занятости вернулся за 2 секунды. Снимок 2400 × 1600 обработался за 38,5 секунды, повтор загрузки 800 × 564 — за 10,7 секунды.

На обоих PNG сохранился размер, а пиксели вне обнаруженных областей остались прежними. В обнаруженных областях снизилась детализация. Это контрольные образцы и один прогон в локальном окружении.

Отдельно проверили приватность бакета и выдачу одного и того же обработанного файла участнику и организатору после отправки. Повтор загрузки сохранил один объект. После ручного удаления принятого снимка файл исчез из S3, а рассказ и 100 XP остались. Для снимка с истёкшим сроком доступ закрылся сразу, фоновый обработчик затем удалил объект из S3. Проверка через Moto оставляет приёмку настоящего Backblaze B2 открытой.

## Прогулка на телефонах

Подготовьте организатора и двух участников с отдельными аккаунтами. Выберите три доступные для съёмки точки. Один из участников заранее посещает одну точку обычным способом, чтобы проверить повторную награду.

1. Организатор создаёт, публикует и запускает маршрут. Оба участника входят по коду. До старта они видят только название прогулки и число этапов.
2. Первый участник делает снимок у точки. В приложении и у организатора отображается обработанная версия. Организатор отклоняет работу с комментарием, участник переснимает. После принятия открываются рассказ и следующая подсказка. Второй участник остаётся на своём этапе.
3. Первый участник проходит три точки. За новые точки начисляется по 100 XP, за ранее открытое место — 0 XP. На финише отображаются три места, время и суммарные XP. После перезапуска результат сохраняется.
4. На другой прогулке организатор закрывает запуск, пока один снимок ждёт проверки. Вход по коду и новые отправки закрываются. Организатор может принять уже отправленный снимок.

## Сеть, камера и GPS

- Отключите сеть после снимка, закройте приложение и откройте его снова. Снимок восстанавливается либо приложение сообщает, что временный файл удалён системой.
- Отключите сеть при загрузке и отдельно после нажатия «Отправить на проверку». После подключения приложение проверяет состояние прежней попытки. В очереди появляется одна работа.
- Запретите доступ к камере и GPS. Проверьте восстановление через настройки. Отправьте работу вне радиуса 70 м, при точности хуже 30 м и с несвежей фиксацией. После свежего измерения тот же обработанный снимок можно отправить без пересъёмки.
- Отправьте несколько снимков одновременно с разных телефонов. Зафиксируйте время до обработанного предпросмотра, число ответов о занятой обработке и успешные повторы. Проверьте отдельно первый запрос после простоя внешнего сервера.
- На разных дистанциях проверьте размытие на согласованных тестовых снимках. Наличие обработки само по себе не гарантирует, что модель заметит каждое лицо.

## Удаление и выпуск

- После удаления принятого фото участник видит рассказ, пройденную точку и неизменные XP. Организатор больше не может открыть удалённый снимок.
- Во внешнем хранилище проверьте, что очередь удаляет объекты отклонённых, истёкших, отозванных и удалённых работ.
- Для выпуска нужны миграции 17–20, приватное хранилище и включённый Deface. Проверка Render и Backblaze, сборка APK и полевой пилот выполняются в рамках общего выпуска.
