Реализовано 21 октября 2026 года, досрочно по плану. Программная часть готова;
новый профиль на физическом телефоне ещё не проверен. Контрольная точка дня 28

## Сервер

`GET /v1/me/progress` требует Bearer access token. Владелец берётся только из
проверенной сессии; параметры запроса не выбирают пользователя. Ответ приватный,
`Cache-Control: no-store`, стандартные Request ID и безопасные ошибки. Новый
endpoint зарегистрирован в OpenAPI 0.6.0 и в шаблонах логирования.

Пример после первого подтверждённого места:

```json
{
  "total_xp": 100,
  "level": 2,
  "level_start_xp": 100,
  "next_level_xp": 300,
  "xp_to_next_level": 200
}
```

Один SQL SELECT получает SUM(amount) из `xp_transactions` по owner ID. Все поля
вычисляются из этой суммы одного snapshot; отдельного изменяемого счётчика нет.
Запрос не соединяет visits/photos, поэтому скрытие истории и удаление фото
не уменьшают XP. Повторы/конкуренция регулируются атомарным начислением дня 25.
Прогресс не добавляет наград и не изменяет данные.

Фиксированные пороги уровней 1–10: **0/100/300/600/1000/1500/2100/2800/3600/4500**.
На точном пороге уже действует новый уровень. На уровне 10 XP продолжает расти,
`next_level_xp` и `xp_to_next_level` возвращаются `null`. Без посещений: 0 XP,
уровень 1, начало 0, следующий порог 100, остаток 100. Отрицательный XP не принимается
расчётом; в журнале БД amount ограничен положительной первой наградой 100 XP.

Миграций и новых продуктовых правил не добавлено; использована утверждённая таблица
[правил игры](game-rules.md).

## Приложение

Профиль авторизованного пользователя показывает серверный XP, уровень и полосу
прогресса до следующего уровня; на максимальном — соответствующее сообщение.
Клиент получает границы с сервера, не дублирует таблицу уровней и не прибавляет
награду локально. Полоса не округляется до 100% до достижения порога.

- Новый запрос при открытии/возврате в профиль, возврате из фона и ручном обновлении.
- После confirmed на экране фото есть **Посмотреть прогресс**: переход в профиль
  вызывает чтение актуальной суммы, включая подтверждения после replay.
- На загрузке — индикатор; при ошибке сети/сервера — сообщение и повтор с Request ID.
  Невозможность загрузить прогресс не отображается как 0 XP.
- Компонент привязан ключом к user ID; запрос использует `withAccess(..., owner)`.
  При смене аккаунта прежний запрос отменяется, результат не попадает новому владельцу.
- Клиент проверяет целые безопасные числа, границы уровня, nullable-поля и равенство
  остатка `next_level_xp - total_xp`.

Новых native-зависимостей нет; остаётся Expo Go. История посещений, личная карта,
достижения и коллекции в этот этап не входят.

## Проверки

- Go unit: каждый точный порог, значения до/после него, 0, максимальный уровень,
  XP выше 4500 и MaxInt64, отрицательное значение.
- PostgreSQL: независимые тестовые город/три места/пользователь; суммы 100/200/300,
  уровень 3 при 300, сохранение суммы после скрытия visits и удаления photos.
  Фикстуры не требуют импорта каталога и подходят чистой CI БД после миграций.
- Тесты реального подтверждения: owner progress после rejected/retry, параллельных
  запросов и удаления фото/скрытия истории; другой owner до первой награды имеет 0,
  после параллельной первой награды — ровно 100 XP и уровень 2.
- HTTP: авторизация, no-store, session owner вместо подставленного user_id,
  приватность ошибок и шаблон логирования.
- Mobile: decoder/API bearer GET, нулевой и максимальный уровни, неверные ответы,
  offline/401/500, доля прогресса и отсутствие 100% перед следующим порогом.
- Полные Go-тесты с `-race` и тестовой PostgreSQL, `go vet`, gofmt/diff check.
- Mobile typecheck/lint и все 12 файлов тестов; offline Android export:
  `/tmp/vandrouka-day29-export` (Hermes bundle около 3 MB).
- OpenAPI: 28 примеров, 19 реализованных endpoint соответствуют коду.
- Обновлённый `scripts/verify_game_loop.mjs` прошёл на локальных API/PostgreSQL/MinIO:
  два аккаунта, 0 → 100 XP / уровень 2, next=300, remaining=200; повтор +0,
  отказ/исправление, restart/replay, refresh, сохранение progress после явного удаления
  confirmed photo. Тестовые аккаунты/фото удалены в finally.

Native камера/GPS/SecureStore и визуальный профиль на телефоне этим smoke не проверены.
Mapbox не вызывался; эмулятор не запускался. Коммит и push не выполнялись.

## Проверить на телефоне

1. После перезагрузки Expo открыть профиль нового аккаунта: 0 XP, уровень 1,
   до уровня 2 — 100 XP. Гость не видит приватного прогресса.
2. Пройти фото/upload/confirm возле места; открыть **Посмотреть прогресс**:
   после первого нового места 100 XP, уровень 2, до уровня 3 — 200 XP.
3. Новое фото того же места и повторное посещение: сумма остаётся прежней.
4. После третьего уникального места: 300 XP и уровень 3, до уровня 4 — 300 XP.
5. Перезапустить приложение: прогресс сохраняется. Отключить сеть: ошибка/повтор,
   без ложного нулевого баланса; восстановить сеть и обновить.
6. Сменить аккаунт: прежние XP/уровень не показываются. Проверить фон/возврат.
