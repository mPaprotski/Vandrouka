# 11 ноября — повторное поле и регрессия

Это этап плана, выполненный заранее 6 ноября 2026 года. Локальные проверки
не заменяют повторную прогулку. Полевого отчёта за дни 9–10, подтверждённого
самостоятельного APK и публичного API пока нет.

## Локальная проверка

- Мобильные тесты: 20 файлов, без ошибок; typecheck и lint пройдены.
- OpenAPI: 23 endpoint и 29 примеров, проверка пройдена.
- Форматирование Go: файлов, требующих gofmt, нет.
- Полный `go test ./... -race -count=1 -timeout 2m` с отдельной локальной
  тестовой PostgreSQL пройден; `go vet ./...` пройден.
- Локальный интеграционный игровой цикл пройден на API/PostgreSQL/MinIO:
  два аккаунта, восстановление/refresh сессии, потеря ответа upload и confirm,
  точный повтор подтверждения, +100/0 XP, отказ GPS и исправление фиксации,
  изоляция фотографий, история/пагинация, личная карта, удаление истории
  с сохранением XP и достижений/коллекции, удаление аккаунта с отзывом сессий.

Интеграционный сценарий использует тестовые фото и GPS, временные аккаунты
и очистку. Физическую камеру, GPS и SecureStore он не проверяет. Mapbox
не вызывался, эмулятор не запускался. Коммита и публикации нет.

## Повторная проверка на телефоне

1. Выполнить prerequisites и preflight из [дней 9–10](day-09-10-november-field.md).
   Зафиксировать SHA256 APK, версию backend и API origin. Не смешивать результаты
   разных сборок; Expo Go отметить отдельно как репетицию.
2. Скопировать [шаблон отчёта](field-report-template.md) для повторного прохода.
   Для каждого прежнего дефекта записать его номер, исправление и фактический
   результат исходных шагов. Сейчас подтверждённых полевых дефектов нет.
3. На телефоне проверить отказ в доступе к камере и геолокации, затем выдачу
   разрешений через настройки. Приложение не должно зависать или выдавать XP
   без подтверждения сервера.
4. Пройти три точки коллекции. Сохранить фактические GPS/accuracy и результат
   без публикации личных координат. Первое открытие даёт +100 XP, повтор — 0;
   серверный радиус 70 м, точность до 30 м. Не подменять GPS ради PASS.
5. Проверить отсутствие сети перед upload и после отправки confirm, затем
   восстановить сеть и повторить. Для неизвестного результата подтверждения
   сохраняется тот же ключ; повторной награды быть не должно.
6. Перезапустить приложение, проверить историю, фото, XP, уровни и коллекцию.
   Выйти и войти другим аккаунтом: приватные данные первого не показываются.
7. На тестовом аккаунте повторить удаление фото/истории: XP и прогресс остаются.
   Удалить тестовый аккаунт: старые сессии больше не работают.
8. Записать PASS/FAIL/BLOCKED, request ID без секретов, ограничения и версию
   сборки. После исправления повторить исходный сценарий на новой сборке.

## Условие закрытия

Повторный полевой отчёт на целевой сборке заполнен фактическими результатами;
блокирующие дефекты исправлены и проверены повторно, ограничения перечислены.
До этого день 11 остаётся открытым. Новые игровые функции не добавляются.
